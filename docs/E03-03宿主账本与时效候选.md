# E03-03 宿主私有账本和发送时效候选

本地内部候选，未安装到正式 HTTP 路由、未经过独立技术验收；R6 原包和 E03 已验收权重 33% 不变。

## 实际链路

`openEvidenceHost` 的 `sendLivePacketCandidate` 和 `sendLivePacketPageCandidate` 在服务端维护范围绑定的进程内 Packet 账本。首包与每个独立分页都要求原 workspace ticket 和同一真实 Session，重新读取受权事件及同版 Trip State；调用者提供的任务内容必须与注册时服务端保管的 keyed 摘要一致。翻页按原 Packet 的服务器生成 ID、时刻、Context ID 和预算重建固定快照，比较候选摘要，并只从私有账本判断哪些正文已经发送；客户端不能提供 delivered 清单。

账本长期仅持有随机密钥、keyed 摘要、范围与时效元数据和 delivered 身份摘要，不保存 Packet 原话、Task 明文或明文对象 ID。注册成功的受信 Task/Focus 输入现在由宿主以每工作区临时 AES-GCM 密钥封存在内存，最多五分钟；首包和独立分页从该租约取回，在真实 Session、PG、E11 来源和当前 TS 事务中重验原 Turn/Task keyed 摘要。删除、恢复、释放工作区、宿主关闭和租约到期会清除密文缓冲及本地 Packet 账本。重复登记可重新签发短租约。HTTP 页请求只有原 R6 `page-request`，客户端不需要也不能补传 Task 原文。受限租约是单进程任务提供器：重启、跨进程路由或租约到期后旧 Turn 不能分页，需重新建立受信 Turn；它尚不是可跨进程恢复的持久任务仓库。JavaScript 字符串、请求栈和网络缓冲不能物理擦除；数据库或身份服务异常挂起时，瞬时明文的严格清除时限仍未证明。

新增 `packet-http-candidate.ts` 提供真实 Node `IncomingMessage/ServerResponse` 的 `/runtime/trips/:id/assemble` 与 `/runtime/trips/:id/pages` 内部 HTTP 处理器。受信服务端在 Turn 登记成功后以不透明工作区票据 `bindTurn`；路由绑定本身最多五分钟和 256 个 Turn。请求先检查真实 Cookie Session/成员和 Origin，再按冻结的 assemble/page-request schema 解码；宿主再次在数据库事务中核对旅行、工作区、来源、任务及状态。独立页只凭服务器已有 Packet 账本选择工作区，用户提供的 packet_id 不是授权凭证。真实 Session/PG/回环 socket 测试已覆盖首包、分页、另一成员、错误 Origin、伪造 delivered、删除及旧 Turn 拒绝。测试的城市与用户输入仍是合成夹具，真实模型解释/任务生成和产品数据源未接入。

此处理器尚未挂到 Next 公开路由：现有 Next Route Handler 只暴露 Web `Request/Response`，无法提供当前账本所依赖的 Node socket `finish` 信号；公开 E11/HTTP 入口还需工程计划规定的技术审核。生产接线需明确 Node HTTP 宿主方案和受信 Turn 绑定入口，补跨进程删除/撤权通知、可信生命周期写入、自动到期清理、备份/WAL 清理及故障/重启语义。`finish` 仅表示本机传输交接，先前已排队的字节不能撤回；到期与发送启动之间的保守时钟检查降低间隙，但任意进程暂停下的绝对零间隙没有可行证明，需按既有合同审定线性化点。

在真实 PG 事务中锁定 Session/成员、工作区、来源和状态，最终检查通过后同步开始 socket 排队；数据库事务提交后不持锁等待网络完成。宿主自身在实际提交后调用 `afterCommit`，随后通过新的受权事务重建并复验，再确认本机 socket `finish` 才更新私有账本。每个包仅允许一个待完成发送，竞争请求失败，可重试；失败、事务不确定或复验失败使该包失效，不能声称未发出的字节已被收回。`finish` 只表示本机传输层交接，不证明客户端收到、理解或持久确认。

同进程持久接受删除、恢复、释放或关闭时清除对应账本；过期账本最多按 Context 截止或五分钟关闭。其他进程完成删除或撤权后，下一次读取/复验会失败并使账本失效；数据库持久 retention revision／到期标记为跨进程失效提供基础，尚未实现即时通知。E11 读取候选仅允许经验证的同工作区 Task 来源关联续期，按最后相关交互 +180 天、单事件 +12 个日历月及可信旅行结束 +30 天取最早边界；未关联事件仍按自身记录时间 +180 天。维护候选以有界扫描持久标记到期，独立事务清除正文；清理失败保持停读并重试。当前没有生产调度、可信旅行生命周期写入、备份/WAL 处置，也不能把测试生命周期数据当作实际产品事实。

## 发送前期限

内部受限 E11 数据库函数在授权后返回从数据库时钟计算的剩余时间下界，覆盖当前 Session、事件记录 +180 天、+12 个月、已知旅行结束 +30 天。宿主还按数据库时钟检查 Context 截止，并保守涵盖同版状态内**所有**事实的观察和过期边界，包括未被选中的事实；每个数据库请求从请求前的本机单调时钟与墙钟起算，向下取整并留出至少 1 毫秒余量。在 JSON 编码之后、写头之前以及写头后写正文之前检查两套本机截止，任何一项越界就失败关闭。这可能比实际截止稍早拒绝，是有意的保守技术限制。

真实 PG 反例在最终数据库检查后暂停，分别令 Session 到期、原事件到期及未选中事实开始生效，三个场景均在正文发出前被拒绝；独立 socket 测试还模拟写头期间跨过本机截止，连接关闭且不记账。这些测试不证明进程在最终本机时钟检查与内核排队之间遭任意暂停、机器睡眠且时钟异常、远端数据库时钟突变时有绝对零间隙，也不证明流式逐块输出安全。当前一次性缓冲整个 JSON；序列化和排队仍占用事务时间，没有完整响应大小/耗时 SLA。

删除/撤权若先提交，后续发起的读取失败；读取事务先持锁并启动发送时，删除/撤权提交等待锁释放。把最后有效检查/启动发送视为读取线性化点是对原批准合同的工程解释，仍需技术负责人核准；后到达的网络字节无法收回。若产品要求删除回执后不再收到此前已进入网络的字节，原 Owner 文本未明确这一更强承诺，需要单独裁定。用户身份、跨进程缓存失效、备份/WAL 与实际产品端的交付确认仍不能由本候选推断完成。

## 验证与后续

本地真实 Session/PG/回环 socket 专项验证首包、同包独立页、跨主体/工作区、伪造交付清单、删除后旧包失效、新工作隔离、事务提交后撤权、发送前 Session/事件到期和未选中事实边界。另有受控多任务／继续／焦点、相关交互续期、自然到期标记与失败重试的真实 PG 反例。三个相关测试文件本地 **56/56 通过**；追加的过期生命周期版本负例单独复验通过；TypeScript、相关 lint 和 Next build 通过，原包来源与 DC 合同检查沿用前一提交的通过记录。本地测试不是远端 CI。真实 `next start` 已通过单实例本机网关代理 `/api/health` 返回 200，E03 路径按预期分流。代码及 SQL 是候选，未加入正式生产迁移或公开路由；真实模型、生产调度、跨进程即时通知、可信生命周期和备份清理仍需完成，且须同一集成版本独立安全/技术复核后才能纳入 E03-03 最终验收。
