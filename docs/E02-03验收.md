## 表示范围与内部接口边界

PostgreSQL signed BigInt 为 −2^63 到 2^63−1，非负上限 9,223,372,036,854,775,807；JavaScript number 的精确整数上限为 2^53−1，即 9,007,199,254,740,991。原 Schema 的 integer 未增加 maximum、未缩减正式契约。当前 TS 执行器遇到不可精确表示的 revision/version/引用版本明确报 `INTEGER_REPRESENTATION`，拒绝读取或写入，不做截断、舍入或自动降级；需要更宽运行表示时须单独审核表示与传输方案。

原始 JSON 字符串使用 Node 24 reviver 的 source token 检查，避免小数在 JSON.parse 后伪装成安全整数。数据库 JSONB 亦先读 text，避免 pg 驱动先舍入。内部直接传入的 JS 对象须由可信宿主保持精度；已经在上游解析丢失的信息无法事后恢复，外部 JSON 接入应保留原文走受控解码，HTTP 适配留待 E02-05。

`openTripCommandService(connection, host)` 是内部库：host.authorize 必须完成真实身份认证与该 trip 授权，返回可信 Actor；库无默认 user 授权。`createTrip` 只允许授权 System 创建原契约的空根；`submit` 只接受正式命令，state/history 也检查宿主授权。当前测试用不可伪造的合成对象凭据映射证明边界，没有宣称真实登录系统已经建成。运行 DB 身份仍是独立非 owner；有运行数据库凭据本身就是受信边界，不能把其分发给不可信调用者。没有添加任何业务 HTTP 路由。

本切片写入仅支持 A 所需的 DestinationEntity/TripGoal/Preference/Candidate/Decision 及传播形成的 OpenIssue。已有 Constraint/ExternalFact/Skeleton 的状态可完整读取与静态校验，但写入会明确返回能力边界错误 `E02_SLICE_UNSUPPORTED`，避免半处理未实现机制。此错误不是新增业务规则或状态。非 User 引发的待确认操作也拒绝执行；不谎称已保存 pending，不冒充 User。其他命令、既有确认决定的反转、非 activate 的生命周期入口尚未开放。
