# E04｜行动状态的纯转换切片

依据已选 NAP R3 `engineering/runtime.md` RT-02/RT-05 和 `engineering/contracts.schema.json` 中 ActionRecord.phase。来源锁 `specs/nap-r3-2026-11-06/selection.json` SHA-256 为 `c24a942588cb54fab20a3b66cd104d9d273f25aba259794605572ab9f7c5e952`。R3 已在规格、追溯与合成参考范围获限定复核；C3/发布基线 Owner 最终审核、真实运行和跨模块验收仍未完成。基于未合并的 #19 边界测试分支；#19 的原有内存自洽切片仅对旧固定 head 限定接受，新测试提交须另复核。

`nextActionPhase` 只根据当前 phase 与调用方给定的事件和布尔判断，计算候选 phase 和是否需要查权威回执，不执行、存储或提交。它覆盖：

- proposed 的结构及资格检查；eligible 的必要等待和已认领启动；eligible/waiting_user 的失效；经校验反馈后恢复 eligible；已由宿主确认的非运行中取消。
- running 的成功、部分、失败以及返回时依据已变 stale；业务结果未知保持 running 并返回 `receiptLookupRequired=true`。blocked、partial、succeeded、failed、stale、cancelled 均不能原位重启。
- 缺失、非法类型、额外字段、错误 phase/event 组合及缺少启动/反馈/取消判断均抛错，不自行推定成功或修改输入。未知结果的查回执要求不会调用任何业务 API。

## 不可替代的宿主责任

布尔判断只是调用者声称的条件，函数不能证明事件来自真实用户、身份或授权有效、原 Packet 当前、步骤已实际认领、结果已产生或回执已保存。不能把其输出当成权威 ActionRecord、执行许可、真实交付或用户选择；模型、客户端和请求体不能自行提供可被信任的判断。真实实现必须由可信宿主在同一主体、旅行、工作区及当前运行代次下验证来源/权限、进行数据库原子认领和持久化、处理 CAS/幂等及故障，必要时重新读取 TS/DC 并复核时效和授权。

运行中取消按 R3 属于尽力中止，本纯函数不直接把 running 改成 cancelled；真实取消与外部副作用的结果必须由可信宿主处理和对账。此切片不实现 dispatch、decide、工具、HTTP、持久日志、跨进程恢复或用户界面。原始数字 token、14 项来源行为、真实模型/工具以及完整 C3/E05 评测仍须独立验证；既有 E02 HTTP 回归不是 NAP 接口验收。本分支不修改共享 NAP 原包，不合并或部署。
