## 4. DC 0.1.0 拟采用机器契约选择

以下全选为**待确认候选**，URI 统一 `https://decision-context.example/runtime/0.1/<name>.schema.json`；每份源 SHA、旧来源及离线文件绑定在 selection.json。TS 的 `schema_version=0.1.0`、只读 DecisionContext `$id` 和业务对象不变；运行封装不进入 state.objects。

| 类别 | 必须保留的 Schema |
| --- | --- |
| 本轮与读取 | open-turn、turn、assemble、packet、page-request、page |
| 受控写入和错误封装 | change、confirm、error；内部 request/response 仍引用原 TS 契约 |
| 持久现场 | checkpoint-payload；checkpoint_format_version=1，参考 SQLite user_version=1 |
| 保存、恢复、删除及回执 | scene-save、scene-restore、scene-delete、scene-ack、scene-restored |
| 发现、状态查询及仅重试保存 | scene-list、scene-list-result、scene-status、scene-status-result、scene-retry |

两边工程接口表保持相同 11 个逻辑 POST 接口：`/runtime/trips/{trip_id}/` 下的 turns、assemble、pages、changes、confirm，以及 checkpoints/save、restore、delete、list、status、retry。它们是来源规格的逻辑协议，**不是本轮新增的 Next.js 路由**。TS §8 原 `POST /trips/{id}/decision-context` 的只读契约依然保留，如何与运行封装接入须在确认基线后的 E03 实施中审核，不以本轮静态检查冒充接口实现。

恢复能力完整纳入同一 0.1.0，保留以下原机制：

| 原约束 | 对应来源/选择 |
| --- | --- |
| 问题身份、关联、暂停/处理状态、焦点恢复 | 范围决策 DC-R01/R07、恢复规格 §1/4/6；task、focus_keys、saved task |
| 比较版本、语义视图、未提交/假设草稿与原话 | DC-R01/R03、恢复规格 §4；view/draft/checkpoint，不成为第二份业务真值 |
| 精确性以最后成功保存且有回执的点为界 | DC-R06、恢复规格 §3/5；scene-ack、CAS、幂等、丢回执仅重试保存 |
| 最新权威状态、事实时效及缺失/陈旧说明重建 | DC-R02、恢复规格 §6；scene-restored、重建 Packet，不恢复旧读取包 |
| 旧采用、草稿与旧授权不能复活 | DC-R04、恢复规格 §6；恢复输入只读、新 runtime_id，原确认守卫继续有效 |
| 用户/旅行/工作区隔离与竞争检测 | DC-R05、恢复规格 §5/7；owner 来自宿主，不接受客户端自报 |
| 暂缓不因重开会话自动催办或结束 | DC-R07、恢复规格 §6；deferred/reopened 按当前权威对象判定，不实现 Policy 路由 |

上述为原条款的交接，不是本轮实现的恢复引擎。SQLite 只是原参考适配，不自动成为本 Next.js/PostgreSQL 工程的生产存储选择；真实宿主 WriteGrant、工作区隐私、检查点原子性及恢复 HTTP（含原 503 错误）仍须在 E03 切片独立开发验收。
