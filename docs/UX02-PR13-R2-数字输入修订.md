## 修订和红转绿

在 Node 24 JSON reviver 收到原始 source token 时，恢复预览将原六个计数字段与 `source_version`、`insert_at` 一并传入整数精度校验；Zod仍负责该接口正数/非负和范围约束。`1.00000000000000001`、`1.99999999999999999`、超过安全整数的 token 不会先舍入为合法版本或位置；精确整数表达 `1.0`、`1e0`、`1e2` 等继续接受。错误为原 `INTEGER_REPRESENTATION`，无候选请求和业务写入。

修复前，使用原始 JSON 字符串的3项路由反例均失败：source_version 两个精度损失案例分别进入内部错误／错误版本路径，insert_at 进入范围错误路径；修复后 3 项通过。真实 Next.js/PG 额外使用手写原始JSON测试两字段非整数、溢出，以及合法小数/指数表示，检查四业务表指纹不变；不先用 JavaScript Number/JSON.stringify 生成这些数字。
