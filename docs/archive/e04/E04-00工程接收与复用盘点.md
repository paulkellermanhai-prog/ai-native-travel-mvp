## 当前接口差异

1. 旧候选的 `context-basis-preflight.ts` 只读取早期 Context ticket，明确不能证明 Packet、Turn/Task 所有权或交付；E04-01 必须改接 E03 最终宿主持有的 DC `packet`。
2. 旧 Schema 路径为 `nap-candidate-2026-11-06`。首批代码保持内容不变以便审计，但运行错误和文档不再把结构通过描述为执行授权。
3. E03 最终宿主私有保存真实 Packet；现有公开方法主要面向 HTTP 发送和写桥。E04 需要一个窄的只读宿主端口，按当前 Session/Trip/runtime/revision/TTL 重新验证后返回不可变副本，不能接受客户端同形 JSON。
4. 旧 Action phase 与 completion binding 都是纯函数；真正持久 ActionRecord、原子 Step claim、工具调用账本和恢复在 E04-03/05 实现。
5. CT-05 RequestObservation 尚无持久层；它属于 NAP 运行事实，不进入 TS 对象或 DC Checkpoint。
