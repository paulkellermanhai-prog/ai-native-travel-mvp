## 1. 实现边界

- `tool-capabilities.ts` 是可信宿主固定注册表；只开放 `egypt-transport-synthetic-v1` 的只读 HTTP query 和 `egypt-cost-subtotal-v1` 的确定性 calculate。能力、provider、参数结构、超时和事实等级不能由模型动态声明。
- `002-tool-results.sql`、`tool-runtime-store.ts` 保存不可变调用与完成绑定，关联 owner、Trip、workspace、runtime、Decision、Action、Step、capability、provider、查询摘要、basis revision、结果状态和当前可用性。
- `tool-dispatch.ts` 在原 Action/Step 认领后执行工具；交通观察只以 Tool actor 经 E02 `ingest_fact` 写入，NAP 账本不成为第二份旅行事实。明确的事实写入拒绝不会被记成成功或当前可用。
- 结果状态保持 `result/partial/empty/timeout/error/no_service` 六分；timeout/empty 不提升为 no_service，分项费用不提升为全程预算。
- 晚到、重复 dispatch、revision 改变、runtime/Session/membership 失效、查询条件改变和结果 TTL 到期均不能继续支持当前判断；历史回执仍保留。
- `tool_result/state_change` 必须由完成账本证明；未注册 trigger 继续 fail closed。G05 产生新 DecisionPlan，不原位复活旧 Action。
- 合成交通响应明确带 `synthetic:true`，不表示真实班次、票价、可预订性或供应商接入。

## 2. 最小收口

- 费用结论强度：`cost.calculate` 不再把调用方列出的 `required_categories` 当作全程覆盖证明。埃及内部 MVP 当前只输出已知分项小计、`known_items_only` 口径、已知缺项和 `unlisted_trip_costs`；没有独立可信的全程覆盖证明时，`is_full_trip_total` 恒为 `false`。
- 未知结果对账：若 Tool actor 已由 E02 成功写入 ExternalFact，随后 lifecycle 同步或 ToolCompletion 保存失败，Step 保存原 invocation、原结果和原 E02 请求的恢复绑定。再次 dispatch 只查询原 ToolInvocation 与 E02 `tool` 域权威幂等回执，然后补齐 lifecycle、ToolCompletion 和 Step，不重新调用 HTTP 工具，也不重复写入事实。
- 无正文边界：恢复绑定或权威回执正文缺失时保持 `execution_unknown`，不伪造成功，不自动重做外部动作；测试通过新的合法 Decision 继续。
