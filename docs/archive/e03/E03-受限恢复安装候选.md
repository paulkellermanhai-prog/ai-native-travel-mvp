## 存储及读取

E11 契约明确正文不写 Checkpoint；原本地 `aceb800` 候选将任务原话写入 `e03_checkpoint.heads.payload`，不应作为该边界完成。这里调整为 Checkpoint 仅保存内部来源引用，原格式 1 的临时内容放在同事务、限权的 E11 `HostEvidenceScene`；幂等键写前转为范围绑定 HMAC。此伴随表仍含敏感正文，继承 E11 的删除/期限/备份责任，不能拿“换表”宣称隐私策略已完成。当前只是候选 SQL，未迁移或上线。

保存与关联来源在同一事务锁定实际 Session、成员、工作区、状态、所有来源和 checkpoint；主动删除源时若伴随内容依赖它，则同时清除伴随正文、checkpoint 引用和幂等回执；无关事件不清除其他现场。恢复读取只供可信宿主进程内部，验 scope、同一最新 TS 快照、checkpoint 引用/摘要、全部已知来源、删除和期限；旧保存点可与更新的当前 TS 进行只读分类，但可信生命周期行仍须与当前 revision 匹配。后续恢复安装之前再次验证来源、Session、checkpoint 版本与期限；不得以旧现场授权写 TS。

## 本次内部安装与交付边界

`restoreCheckpoint` 仅在同一宿主进程、同一已绑定 Session 和 workspace ticket 上运行；从完整保存点读取后检查格式与摘要，将任务的种类/进程、范围绑定的 keyed 指纹及来源令牌安装到本地身份索引，丢弃旧事件回执和本进程缓存并产生新 runtime_id。返回 checkpoint/revision/任务数量的内部元数据，不返回原话、焦点、草稿、Packet、Grant 或正式 `scene-restored`。它没有安装完整任务或恢复 Turn，因此不声称恢复了完整用户现场或旧授权已在其他服务失效。所有后续任务继续受实时来源、授权及时效复验约束。

事件记录与恢复读取对 workspace 行串行；恢复在锁内取该 workspace 已提交事件序号水位。本进程拒绝将水位内任何旧事件（包含未保存事件和间接依赖）重放为新 Turn。恢复期间已发起、尚在队列的记录或保存绑定旧运行代次，恢复完成后拒绝而不写入；恢复后实际新事件可注册。水位和 workspace ticket 目前只存在本进程，不能当作跨进程持久授权。交付线性化点是事务最后一次授权/来源/时效复验并成功提交；数据库不能收回先前已提交或已外发的内容。

该内部候选在事务成功后才切换本地代次；R6 Python 在安装后继续组装和验证，后半段失败时不一定回滚代次。该差异需技术审核，不自动改变正式恢复规则。
