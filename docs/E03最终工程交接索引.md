## E04 NAP 工程接口

E04 应消费现有 DC 0.1.0 `packet` 合同，需要分页时使用 `page-request` / `page`；类型与运行校验入口为 `DecisionContextContracts`和 `parseDCContract()`。Packet 已包含当前 Task、Context、权威对象投影、待处理输入、支持级别与分页清单；NAP 不应直接读 E11 表、Checkpoint 载荷或宿主私有回执。

NAP 如需请求业务变更，必须经过现有 `write-bridge` 与 E02 命令通道。没有精确 User Grant 时只能使用原合同允许的 Model/Proposal 路径，不得确认用户决定、伪造交付记录或绕过当前 Session、Trip、Packet、revision 和时效复验。Checkpoint 与恢复由宿主编排，恢复后必须使用新 Turn/Packet/Grant，不能复活旧写权限。

`/runtime/trips/{id}/turns|assemble|pages|changes|confirm|checkpoints/*` 是受控的内部 MVP 宿主路由，已用真实 Cookie Session、TripMembership 和 PostgreSQL 验证。它们不是未来产品公开 API 的自动批准；公开入口、对外合同、运维和隐私告知须另行审核。

## 已接受限定差异

冻结 R6 与当前 TypeScript 对 `received_at` 第七位非零小数的时间边界判断不完全等价。工程接受当前 TypeScript 更严格的未来时间拒绝策略；该结论不修改冻结 R6 或正式机器合同，也不表述为完全等价。固定对照证据在 `tests/decision-context/task-core/r6-time-boundary.test.ts`。
