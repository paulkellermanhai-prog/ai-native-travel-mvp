# E03-02：受权同版组装与消费候选

基于 #18 联合候选 `33059d42de0a08e3a5a1e072b0e7e99d2af043ff`，依据独立审核任务 `01a1af8d-c1cb-7423-8dba-ecda4ccaf01f` 补 E03-02 三个出口，固定来源 R6，不接入 R7。

`openSessionContextService` 在服务端自行建立真实 Session 与旅行成员 guard，不接收外部注入的 reader、状态、Actor、认证器或时钟。组装时以一次 guard 后的权威快照构建清单、全部选中正文和版本，返回仅在当前进程有效的不可伪造票据；票据绑定 Session、用户与旅行。消费前后均用同一 Cookie 快照复验 Session、成员及当前 TS 快照，再检查 revision、正文摘要、对象版本、保护集合、事实争议与过期；不符合时拒绝交付。无业务数据库写入。

`context-assembly.ts` 将 R6 已批准的对象选择/闭包、保护集合与正文按同一 State 组装；事实清单在全 State 上执行 C12 冲突检测，并在正文注释中限制失效或争议事实、未知范围、未解决问题和待复核决定。条件判断使用完整同版快照的 C12 争议集合，即使相反事实未进入正文也不会将争议条件当作确定；这是对 R6 参考注释仅观察所选对象的限定语义差异，已由技术负责人以 `E03-02-C12-APPLICABILITY-2026-11-06-01` 接受；实现证据和 E03-02 阶段验收仍须独立审核，范围与来源见 [接受记录](e03-02-c12-applicability-acceptance.json)。Context TTL 以 5 分钟和所选事实最近未来到期时间的较小值为准，保留微秒并以 UTC 规范化。消费重新计算清单及注释，不用同 revision 替代时效验证。锁源 Python 仅是测试 Oracle。

此交付是 E03-02 内部只读组装/消费边界：taskId 是未经 Task 服务验证的清单标签，不授予任务或轮次归属；没有生产 HTTP、完整 DC Packet、分页或 Checkpoint。那些需原 E03-03 等阶段的合同和权限链，不能凭本提交声称已实现。组装结果仅在当前服务进程保存，重启后须重新组装；它不是跨进程恢复协议。旧的注入 reader 纯选择包装仍只供有限用途，不能作为授权入口。

真实 Session/PG 测试覆盖会话与旅行绑定、伪造票据、跨用户/旅行、撤权与过期、并发变更、同 revision 事实到期、C12+真实 Session+DC 同版、缺失引用和业务表零写入；使用仅存在于测试中的同步拦截，安排首次消费验证之后、最终复验之前真实撤权、会话过期或另一成员推进版本。最后一次授权/状态读取是交付校验的观察点；不声称该事务结束后与后续外部撤权提交严格原子。原参考语义另有纯测试。最终结果以草稿 PR 当前 head 的完整 CI 和独立复审为准；不合并、不部署。
