## 本次可并行实现

`validatePlanInternalIntegrity` 先调用 #16 原 NAP 结构校验，再验证：同一计划中 action ID 和 step ID 不重复；action 的 packet/task 组合出现在计划自述的 basis；主 action 最多一个；steps 依赖存在且无环；只有 read/query/calculate 可携带 arguments，只有 change 有非空 change_request，ask/deliver 需要用户文案。无 action 的正常回应合法；步骤可跨 action 依赖，使用迭代图算法检查。失败不产生部分结果或副作用。

本函数只接受内存中的候选计划、自称的 basis 和引用。即使计划自洽，basis 也可能伪造、过期、跨用户，来源、真实主体与任务、完整分页/交付、当前状态和 G02 资格都尚未核验；测试明确保留伪造但自洽输入的限制。函数没有原始 JSON 数字 token 检查，不是 HTTP、鉴权或执行边界，也不建立服务、模型、工具、数据库、真实用户读取或写路径。禁止据其成功执行行动。
