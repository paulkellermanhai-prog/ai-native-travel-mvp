# 文件管理规则

## 放置位置

| 内容 | 位置 | 管理方式 |
|---|---|---|
| 日常入口、助手规则和工具配置 | 根目录 | README、AGENTS、启动器、package/锁文件、框架配置；不再添加重复工程目录 |
| 本地网页与原型数据 | `prototypes/egypt-trip/` | HTML、JS、CSS 和素材在此维护；保持素材来源说明 |
| 正式业务代码 | `src/` | 按 auth/http/trip-state/decision-context/next-action-policy 边界维护 |
| 正式迁移和模块 SQL | `prisma/` 及现有模块 SQL 目录 | 区分测试安装与正式迁移；不为整理擅自改部署链 |
| 测试和合成夹具 | `tests/` | 与业务模块对应；明确合成数据身份 |
| 辅助工具 | `scripts/` | README 登记用途，package scripts 提供常用入口 |
| 当前使用和开发文档 | `docs/`、`docs/development/` | 当前入口描述实际代码；不沿用过时的“尚未实现”判断 |
| 阶段报告和历史回执 | `docs/archive/` | 分 E01/E02/E03/E04、证据与治理类别保存；历史状态不覆盖当前事实 |
| 独立待审补丁 | `handoff/candidates/` | 记录基线、冲突和状态，不能未经审阅覆盖主线 |
| 冻结合同与参考实现 | `specs/` | 保持原路径和字节；源码、测试、CI 正在引用 |
| 依赖、缓存、生成文件 | 已忽略的本机目录 | 不提交；确认可以重建后再清理 |
| 真实凭证和数据库 | 私有环境配置、本机/托管数据库 | 不提交，不放入交付压缩包 |
| 截图、压缩包、个人临时分析 | 仓库之外 | 不在工程里再套一个工程或提交个人工作副本 |

## 删除和移动

先搜索引用，再判断用途。历史、候选、参考 Python、生成契约和素材不能只凭名称判定“没用”。必须检查代码 import、测试文件读取、package 命令、CI、规格清单与动态素材引用。

已经被替代的使用说明可以删除；有独立事实价值的验收和候选归档。冻结快照及历史 JSON 回执按来源保存。本次移除旧的 `docs/工程目录与保留说明.md`，由当前项目地图替代，旧正文可从 Git 基线恢复。

迁移记录写入 [project-cleanup.json](project-cleanup.json)。历史 JSON 内的路径保留当时写法，需要时用该清单将旧位置映射到归档位置。当前 README、交接、进度维护源及 Markdown 导航使用实际新位置。

## 合入前

运行 `npm run project:check`、`npm run specs:verify` 和相关模块测试。修改 E03 进度导航后，用 `python3 scripts/audit-e03-00.py --write-board` 生成看板，再运行脚本复核。无法运行完整环境时，记录失败原因和未验证范围，不调整历史验收状态。

通过分支和 PR 同步；本地整理成功不等于 GitHub 已更新。后续新增文档和脚本同时更新对应目录 README。
