# E03 来源闭包隔离候选（本地，未接入）

## 已完成和不变量

当前本地集成候选还增加 `HostEvidenceSceneEventWitness`：在保存事务中，针对每个实际写入场景的 Task 事件，在通过真实 Session、工作区、来源令牌、事件正文及期限校验后，记录场景引用和事件 ID；不存原文或模型输出。保存失败、提交前回滚不会留下记录，删除场景时通过外键同事务移除记录；重复成功回执可重建同一组正向记录。运行角色无直接表权限，宿主启动时检查直接及继承权限。此表只证明场景包含哪些已验证事件，**不能证明它们是全部输入，也不证明未列出的事件与场景无关**；未知来源、删除后禁存和 TS/草稿限制均未解除。此表及其测试安装方式仍是本地候选，不是正式迁移。

`integration/source-closure-candidate.ts` 是删除影响的纯分类候选，接受单一 owner/trip/workspace 的来源图和一个删除事件。它沿场景、任务及其他派生节点的所有父节点递归检查：完整闭包含删除事件为 `affected`；完整闭包不含该事件为 `independent`；缺节点、缺完整性、空来源、循环、重复身份、跨范围或超限为 `unknown`。`unknown` 必须隔离，不能按无关处理。这个模块不写数据库、清理或放行任何现场。

图中事件用身份而非正文匹配；如果生成 B 的真实输入包括 A，则无论 B 的证据只列出 B 或其 question 是否包含 A 的原文，传递闭包仍应包含 A。不同事件的文字相同也不能证明其关系。结论依赖输入图确实完整：调用方自报、Task 的 evidence 字段、字面匹配及当前 `TaskSource` 均不能证明这一前提。当前宿主**没有**记录模型实际全部输入的可信生产者，不能将 `inputsComplete` 设为真实生产证明，不能据此解除现有保存/恢复屏障。

## 接入建议与阻塞

1. 由受信宿主封闭并记录解释器实际输入，包括事件、历史解释、受版本约束的 TS 对象、系统模板、工具结果及之前场景；所有输出继承完整输入的传递来源。缺失、未受控或超过限制即为未知。不能允许模型或外部调用者自行宣称完整。
2. 将来源边、现场和版本绑定，在同一受授权事务持久化；所有写入和删除统一持有 owner/trip 的持久屏障，并按固定顺序锁定工作区和来源。删除时持久墓碑、按完整反向闭包隔离受影响对象；可证明完整且不依赖该事件的现场才可保留。旧现场和未知来源先隔离，不能倒推它们无关。
3. 读取或恢复前仍须在同一一致快照重新校验真实 Session、旅行/工作区、删除与期限；算法结果不构成交付授权。并发删除、保存、撤权、超期、回执重放和跨进程都需要真实 PostgreSQL 回归。实现所有入口前不能只接新入口，避免旧入口绕过屏障。
4. TS 标识必须连同实际对象版本及其完整派生来源可信绑定；不透明 ID 本身不证明对象无删除来源。草稿也需要受信独立来源及适用的保留合同。此候选未放开 TS ID 或草稿保存。

R6 要求 evidence 按本轮原话匹配，并允许已核验旧证据校准 question；它未要求 question 本身是原话子串。现有更窄子串规则和删除后整个工作区永久禁存均是保守候选，不能称为 R6 最终语义。Checkpoint 格式与 E11 不将原话正文写入 Checkpoint 的兼容方式、派生内容失效与允许的现场降级，仍需沿既有技术审核链裁定；此处不新定产品策略。

跨工作区旧副本缺完整来源，现有按单工作区删除无法确定或清除全部副本；需要先盘点隔离并建立受授权跨域传播边和锁序。自然到期目前仅拒绝使用，真实旅行生命周期与相关交互来源、自动物理清理、备份/WAL、恢复时墓碑重放和网络交付屏障均未完成，也没有自定备份期限。历史和其他工作区的未知副本不能因为这个算法而视作已清除。
