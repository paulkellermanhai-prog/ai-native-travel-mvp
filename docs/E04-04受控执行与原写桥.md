# E04-04｜受控执行与原 E03 写桥

状态：`ACCEPTED`。AI 技术负责人于 2026-11-12 接受固定 PR #36/#37 的内部 MVP 限定增量；见 `e04-01-04-technical-acceptance.json`。不扩及 E04-05 或后续阶段。

## 闭环

`dispatchDecisionStepCandidate()` 仅从宿主持久的不可变 Plan 按 `decision_id/action_id/step_id` 取步骤，不接受调用方重传 Action 或 change-request。新执行依次复验：

1. 当前 Session、Trip membership、workspace/runtime 与主体绑定；
2. 保存 Plan 的 digest 与原 DecisionRequest；
3. 所有 basis Packet 的私有交付账本、Turn/Task/E11 来源、revision、TTL 和完整正文；
4. Action/Step 依赖、状态与 PG 原子认领；
5. 写操作的当前 User Grant 或原 model 保护路径。

`change` 步骤只把保存 Plan 内的原 TS `change-request` 包装为 DC 0.1.0 change envelope，交给既有 `submitChange()` 和 E02 权威事务。NAP 不直接改 snapshot、Proposal、Decision 或幂等回执。

## 真实行为证据

| 路径 | 结果 |
| --- | --- |
| 自主只读准备 | 从当前可信 Packet 返回原对象正文、revision 和 evidence cutoff，Action/Step 成功，TS history/proposal/receipt 计数不变 |
| 普通合法变更 | 真实 Packet → Plan → claim → User Grant → E03 write-bridge → E02，保留原 `applied` 结果与幂等重放 |
| 受保护选择 | 无伪造 Grant；model 提交 `decide_candidate` 只得 `pending_confirmation`，TS 不变；后续仍经原 confirm 链路才 `applied` |
| 不完整正文 | 不得构建可信 DecisionRequest/Plan，无业务写 |
| 旧 revision / 错 Session | dispatch 关闭，无新 history/proposal/receipt |
| 并发撤权 | 写桥事务内 guard 拒绝，TS snapshot 和计数完全不变 |
| 回执丢失 | TS 已提交但生命周期同步抛错时，Action 保持 running/lookup-required；重试精确查 E02 原幂等记录，不二次写入，然后收口 succeeded |
| 假设场景 | 决策器不产生 `change` Action，原 HTTP 反例仍拒绝直接写入 |

最终 E04-04 定向真实 Session/PostgreSQL 17/HTTP 联合回归 2/2 通过（12.70s），TypeScript 与 ESLint 通过。
