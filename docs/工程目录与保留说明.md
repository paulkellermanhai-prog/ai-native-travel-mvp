# MVP 工程目录与保留说明

这是 ANTU MVP 的独立工程文件夹。你日常主要阅读这份说明、README 和验收报告；代码、工具配置与依赖由开发人员或工程助手维护。

## 文件按什么秩序存放

```text
MVP Engineering/
├── README.md                 项目说明与运行方法
├── AGENTS.md                 AI 工程助手的工作边界
├── src/                      应用源码
│   ├── app/                  页面、布局、样式、接口
│   ├── lib/                  工程校验等公共代码
│   └── generated/            Prisma 自动生成的代码，不上传 GitHub
├── tests/                    自动化测试
├── prisma/                   数据库结构定义
├── scripts/                  数据库检查等辅助命令
├── docs/                     工程说明和验证记录
│   ├── 工程目录与保留说明.md  本文件
│   ├── E01-report.md          E01 实际验证报告
│   ├── E01验收复核-2026-10-27.md 本轮实际验收与 E02 条件
│   ├── specification-baseline.json 规格版本、摘要与读取情况
│   ├── evidence/             机器可读的验收结果
│   └── cloud-environment.md   云端环境配置说明
├── package.json              依赖清单和运行命令
├── package-lock.json         准确的依赖版本，必须保留
├── compose.yaml              本地 PostgreSQL 的 Docker 配置
├── *.config.* / tsconfig.json 工程工具配置
├── .env.example              环境变量示例
├── .gitignore                不上传文件的规则
├── .nvmrc / .node-version     Node 版本要求
├── .npmrc                    npm 安装规则
├── .git/                     Git 历史、分支与远程连接，必须保留
├── .tools/                   本机隔离安装的 Node/npm
├── node_modules/             下载的依赖，不上传 GitHub
└── .next/                    构建产物和缓存，不上传 GitHub
```

源码、测试、数据库、辅助脚本、说明文档按职责分目录。`package.json`、锁文件和各项框架配置保留在工程根目录，这是工具查找和运行它们的位置；不为了外观把它们塞进其他分类文件夹。

## 哪些要保留

| 类别 | 文件 | 保留方式 |
| --- | --- | --- |
| 工程核心 | `src/`（自动生成代码除外）、`tests/`、`prisma/`、`scripts/` | 长期保留，纳入 Git |
| 运行与工具配置 | package 文件、框架配置、TypeScript/Lint/测试配置、compose、隐藏配置文件 | 长期保留，纳入 Git |
| 说明与规则 | README、AGENTS、`docs/` | 长期保留，纳入 Git |
| 版本记录 | `.git/` | 在本机保留；它保存提交历史和 GitHub 连接 |
| 本机运行工具 | `.tools/` | 本次保留，避免失去现成的 Node/npm；不上传 GitHub |
| 可重新生成 | `node_modules/`、`.next/`、`src/generated/`、`next-env.d.ts`、`tsconfig.tsbuildinfo` | 本次保留，不上传 GitHub；需要清理时可由工程人员按步骤重新生成 |
| 真实私密配置 | 将来创建的 `.env` 等 | 本机保留，不上传 GitHub；`.env.example` 只保留示例 |

“可以重新生成”不等于现在就要删除。本次整理保留了现有依赖、工具和缓存，没有删除工程文件。

## 与产品资料、GitHub、云环境的关系

产品资料仍在上一级目录。现有正式规格需要从那里读取；本文件夹没有擅自实现 Trip State、Decision Context 或 NAP 业务模块。

本地只是把完整 Git 仓库换了存放位置。GitHub 内仍以 `package.json`、`src/` 等作为仓库根目录下的文件，云环境的 `/workspace/ai-native-travel-mvp` 路径不受这次本地搬迁影响。

目录搬迁本身只改变本机存放位置。本导览与 README 导航在后续 E01 复核中纳入同一工程分支和既有 PR，产品资料正文仍不随之上传。

## 工程命令的位置

工程人员先进入 `MVP Engineering/`，再启用本机工具并检查：

```sh
export PATH="$PWD/.tools/node/bin:$PATH"
npm run check
```

`npm run check` 会验证 Prisma、生成客户端、检查类型与代码规范、运行测试并构建。真实数据库测试需要可用的 PostgreSQL 和 `DATABASE_URL`；没有连接配置时会明确跳过该项，不能将它记成通过。
