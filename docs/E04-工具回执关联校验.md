# E04｜工具回执的内存关联校验

本切片基于 #20 已限定接受的纯状态转换提交 `949dfbd27ca18a334451e4d47d7b713d274768ee`，沿用其尚未合并的 #19/#17/#16/#14 和选定 R3 来源锁。依据 R3 CT-02/CT-03、RT-02/RT-03：工具结果应关联实际的 decision、action、step、查询摘要和提供方；返回后还须重新检查当前条件和可信来源。本次只实现可脱离真实宿主的字段关系，R3 的规格、追溯和合成参考复审不等于 NAP 生产验收。

`validateCompletionBinding` 接收计划、行动记录、工具回执和调用方提供的调用记录四个内存对象。它调用已选 NAP Schema、#17 计划内部一致性校验，检查：

- decision、runtime、action、step 等标识在所给对象中一致，action 确实属于所给计划，step 确实属于该 action 且为 read/query/calculate；能力标识与调用记录一致。
- ActionRecord 标记为 running，plan digest 与调用记录相等；完成回执的 provider、query digest、basis revision 与调用记录相等，计划对应 basis revision 相等且在 JavaScript 安全整数范围内。
- 调用记录的字段完整、类型有效且无额外字段；六种工具状态由原 Schema 保留，不将空结果/失败改为无服务，不推断事实、订单或采用。

这是一项**内存对象关系检查**。调用记录只是入参，不是新持久协议或可信凭证。所有四个对象都可能被伪造；字符串相同不证明真实身份、旅行/工作区所有权、provider 身份、查询真的发生、结果与原查询匹配、数字 token 原文未丢精度或实际 Plan 摘要正确。本函数不计算任何摘要，不读取权威 TS/DC 和当前时钟，也不验证当前 revision、授权撤销、事实适用性、完整分页/交付、能力注册表或真实回执；不做幂等/去重、存储、执行、发起查询或更新状态，不能作为授权、结果真实性或执行资格证明。

返回时状态已经变化或 ActionRecord 不再 running 的回执会在此实时关联比较中被拒绝；**这不表示删除或忽略结果**。可信宿主仍须按权限和隐私规则保留其历史证据、读取当前依据并重新决策，不得以旧结果支持当前结论。真实结果的来源、绑定、期限、同版重验、并发/幂等、合法事实写入以及删除和恢复均须在真实宿主和同一集成提交中另验。原 C3、UX 行为、模型/工具效果未在本切片完成；既有 E02 HTTP 回归不属于 NAP HTTP 接口验收。
