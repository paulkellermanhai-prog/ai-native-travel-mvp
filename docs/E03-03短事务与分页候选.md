# E03-03 短事务交付与独立分页候选

本地隔离候选；未挂载生产接口、未完成阶段验收。R6、E11 Owner 裁决和已验收权重 33% 不变。

## 合同和顺序

R6 要求同版快照与正文、分页前后复验、页失败不记 delivered；delivered 是服务器发送记录，不证明客户端收到或理解。E11 已批准规则要求删除标记持久接受后立即禁止后续读取、分页、解释消费及关联，并重验 Session、成员、主体、旅行、工作区和任务。原文没有要求撤回已发送字节。

本候选采用的工程顺序是：在真实事务持有 Session/成员、工作区/来源、状态等既有锁，读取和校验；最终复验后同步启动 socket 写入；事务提交释放锁，不在事务中等待 socket `finish`；发送结束后另启受权短事务复验，只有首个事务确已提交、socket 正常 `finish` 且复验通过才将对象并入私有账本。删除或撤权若先取得锁并提交，后来的请求必须失败；若读取事务先持锁并启动发送，删除/撤权的提交等待该事务释放锁。**以发送开始之前完成的受权读取作为先后顺序，是对既有“禁止后续读取”规则的工程解释，仍需项目技术审核；不把它写成 Owner 新增裁决。**

当前实现将整个 JSON 编码成内存缓冲后一次 `end`，并非分块流式传输；它避免在事务中等待 socket 完成，但序列化和排队仍占用事务时间，未证明事务耗时上限。原正文预算不限制整个响应，不能据此声称响应内存受完整约束。若后续使用分块传输，需另行定义各块的授权/截止时点、取消及部分发送结果，不能将本次一次性排队的证据直接外推。

网络发送开始后，操作系统缓冲和已送字节无法撤回，客户端可能在删除回执之后才收到此前启动的数据。事务回滚、断线、进程退出或提交结果不确定时可能已发出部分字节；候选不记录成功，清除账本，也不称数据已撤回。`finish` 只表示本地传输层交接，不证明客户端收到或理解。若产品要求删除确认之后客户端绝不能再收到任何先前缓冲字节，现有合同并未明确这种承诺，须先交由技术/产品审核明确，不可假装已实现。

## 当前实现与限制

`host-runtime/packet-short-handoff-candidate.ts` 只在内存保留候选和对象身份的 keyed 摘要、进程内账本及状态，不保存 Packet 原话或明文对象 ID。发送启动与 `afterCommit` 分离，后者等待 socket 并通过安装方提供的独立 postflight 复验；事务失败或结果不明确必须 abort 并关闭账本。单个包一次仅允许一个待完成发送，其他请求拒绝并可重试，避免并发丢账；同一对象重复发送不重复计数。按 Context 截止、最多五分钟清除账本。安装方必须用真实数据库锁及复验、诚实调用 `afterCommit`，这一内部对象本身不是 Session 或删除授权凭证。

仅 `NODE_ENV=test` 的宿主测试钩子允许把账本失效函数登记到真实宿主工作区：同进程受理删除、恢复、释放/关闭或来源复验失败会清除其账本。实际 E03 HTTP 路由仍未安装；当前不同页的真实 Session/PG/socket 试验由测试夹具保存合成 Task 和 Packet，并逐请求经真实宿主复验；**生产宿主尚未提供无原话长期副本的可信 Task 重建与独立分页调用**。本候选也未完成其他进程发起删除时的即时内存失效通知；事件/会话实际更早到期时，在下一次受权复验前仅有 Context 定时清除，不能宣称 E11 全部自动清理完成。

本地竞争测试在受权事务内人为暂停，确认独立数据库删除等待锁，随后发送开始、事务释放、删除持久化；发送后的独立复验看到删除并使账本失效。正常调用的事务代码不等待 socket 完成；测试中的人为等待仅用于观察锁排序。旧候选的发送后复验失败案例仍保留，用于说明不能收回字节。TTL 与 Session 的绝对截止可能在数据库时钟校验和应用进程同步启动发送之间跨越，需技术负责人确认消费时点与保守时钟保障，不能从本测试推断微秒级无间隙或跨机时钟同步。

后续要在正式宿主内持有受会话、旅行、工作区、运行代次和具体 Turn/Task 绑定的私有账本；按固定快照重建而非缓存原话；把当前测试钩子替换为真实独立分页接口；实现跨进程删除/撤权失效、E11 更早截止及时清理、故障与重启处理；再用真实 Session/PG/HTTP 测试跨用户、并发页、过期、撤权、删除、断线和提交不确定性。不应把本次局部结果当作 E03-03 PASS。
