# E03-01-F01｜E11 授权证明身份绑定修复

针对「工程侧｜MVP开发计划」技术回执 `E03-01-PR14-TECH-REVIEW-2026-11-06-01`：获审 head `89d73e30409997e69656e6f9af94a90f420f0bbf` 因 E11 授权证明的身份可能换绑而需修正。R6 Gate A 继续有效；E03-01 仍待增量验收，E03 已验收权重仍为 8%，E03-02 尚未放行。

## 缺陷与修复

原 E11 grant 将调用方可复用 `Headers` 对象留作事务复验凭证；共享 `sessionHost` 以该对象为 WeakMap 键缓存身份，后续认证可能覆盖其对应 session/user，导致旧 grant 的复验使用新身份。即便后一次 E11 的 scope 检查失败，也可能先覆盖该键。

修复在 `src/server/interaction-evidence/boundaries.ts`：每次签发前以当下 Cookie 新建私有 `Headers`，只把这个不可由调用者访问的独立对象交给 `sessionHost`，并与冻结 scope 和 grant 绑定。每次认证独立缓存签发时的 session/user；`guard` 仍逐次通过真实数据库检查该 session 及旅行成员资格。后续修改/重复使用外部对象、成功或失败认证均无法覆盖已有证明。Scope 比较、伪造 grant 拒绝、撤权和会话过期检查不放宽。

## 复现和回归范围

在修复前执行 `tests/interaction-evidence/session-binding.test.ts` 的三个隔离测试，**3/3 失败**：A 后 B 的授权换绑、scope 不匹配/无效 Cookie 失败认证污染、同一 Headers 并发交错均使应拒绝的旧 grant 错误通过。修复后该文件 **3/3 通过**；使用认证、成员和事务查询替身，此红转绿是针对实际源函数的隔离回归，不是 PostgreSQL 验收。

真实 Session/PG 套件新增四项：共享旅行不同成员 A→B 后撤销 A、令 A 会话过期而 B 仍有效；B 与 A scope 不匹配及无效 Cookie 的失败认证；共享 Headers 并发认证；同一用户两个独立 Session 中只使签发 Session 过期。此前伪造 grant、跨 owner/trip/workspace/task、撤权与过期用例继续保留。它们的实测结果以当前修复 head 的 CI 日志为准。

## 公共认证调用检查与后续风险

本次未修改公共 `sessionHost` 或 E02 命令服务。其内部仍以调用方 `Headers` 对象缓存 identity，`openTripCommandService` 在授权与事务 guard 间传递同一对象；因此若其他内部调用方在并发操作中故意或意外复用并更换同一可变 `Headers`，存在同类身份交叉的潜在风险。本次没有对公共服务构造真实 PG 漏洞复现，也没有证实线上事件或可由 HTTP 请求直接利用。

已检查现有 `handleTripHttp`：每个 HTTP 请求在处理时基于 Cookie 新建私有 Headers，并在该请求内顺序调用服务；该观察不等于证明所有内部调用或未来适配器安全。此公共调用契约风险需由 TS/E02 技术负责人独立评估并决定是否修复及影响 PR #11/#13 的范围；不要将 E11 的修复误称为公共服务已修复。E11 后续调用仍须使用此私有快照入口，禁止绕过它将客户端凭证对象当授权证明。
