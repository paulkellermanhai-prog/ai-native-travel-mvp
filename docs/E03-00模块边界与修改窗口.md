# E03-00｜模块责任边界与修改窗口

本页只规划工程责任与修改位置，不分析任何机制迭代差异，不新增接口字段、产品对象、状态或数据库表，也不创建下述未来模块。现有契约和强制守卫优先；可替换策略不等于可关闭保护。

拟定路径只用于定位工程责任。若阶段实施时同一个小模块已经足够，应保留简单函数，不为可替换性预先创建空接口、插件注册器或配置平台。当前没有新增上述生产文件。

## 统一修改原则

稳定校验层必须包住策略层：真实身份/旅行授权 → 原合同和精确数字解码 → 读取/策略输出 → 引用、语义、保护集合与版本复验 → 原受控提交或只读输出。不能让“可替换策略”同时替换认证、确认或数据库安全限制。

未来已批准的变更，只在固定八阶段中登记受影响子任务、依据、测试与风险；先判定其是否影响字段、枚举、引用、权限、版本或历史恢复意义。影响这些正式边界时需要独立规格审核，不能保证所有机制变化都无需修改机器契约。本次不对任何具体机制迭代作判断，也不预留未批准的字段。

## E03-01 的稳定范围与启动条件

Gate A 通过并记录明确批准的候选 SHA/选择清单后，E03-01 只做：

1. 将批准的 20 份 DC Schema 与原 20 TS Schema 接入既有 AJV Draft 2020-12 离线注册和类型生成方式；禁止旧 URI 静默别名，不改业务字段。
2. 复用原始 JSON 数字 token、安全整数拒绝边界和稳定错误约定；明确 schema/contract version 与 checkpoint format/revision 不同。
3. 建立最小参考测试入口、可注入时钟/UUID 与结构夹具，继承 E02 的规格/权限/事务回归；不重造认证、Session、状态数据库。
4. 明确后续模块入口及依赖方向，不实现 Context 选择、Task/Focus 行为、写桥、Checkpoint 数据表、恢复或 HTTP；这些保持 02–07 的责任。

启动前必须具备：技术负责人 Gate A 批准；DC 0.1.0 完整恢复基线与严格版本治理口径确认；原参考包和依赖可获取且来源锁定；原 E02/main CI 无回归；E03-01 切片明确授权。当前参考资料与执行工具已就绪，真正的当前阻塞是 Gate A 与启动授权，**不是缺少其他产品迭代资料**。
