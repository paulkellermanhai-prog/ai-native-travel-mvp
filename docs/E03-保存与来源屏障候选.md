# E03 保存与来源屏障候选

本文件记录 `aceb800` 的历史切片；最新本地恢复候选与原话存储修订见 `E03-受限恢复安装候选.md`。

本切片仅供本地隔离数据库和内部技术审核，不属于正式迁移、对外路由或已验收阶段。冻结 R6、E03-02 验收及 E03 33% 不变。宿主是持有受保护工作区 capability 的可信执行者；数据库角色不能交给不受信代码。SQL 不独立实现完整 R6 schema/Task 守卫，宿主先做合同、来源跨度和任务身份检查，不能把数据库包装称为对任意 SQL 调用者的完整验证。

## 实现

- 宿主在首个异步等待前快照请求；验证实际 Session、旅行和宿主签发工作区。任务身份验证在同一事务写入仅含 capability 盐化任务摘要、事件令牌和范围的候选来源行；同一任务的续接保留先前依赖。它不是完整 E11 关联日志、持久 Task 或新进程身份恢复。
- 受限 `saveCheckpoint` 只接受进程中已验证的未处理任务、无草稿及无错误的合同原样内容；拒绝不支持的部分，不裁剪。数据库同事务锁住 TS 文档、授权、工作区、生命周期、检查点和事件，检查来源正文、引用、entry、时间、全部依赖、删除与期限，并比较同版 TS 的完整对象版本清单；新视图的对象引用和版本须可解析，原样历史视图保留 R6 例外。CAS 和幂等使用原候选仓储；时间和 Session 在锁等待后重验。
- 内部 `inspectCheckpoint` 检查相同来源，但只返回检查点元数据；不交付正文，不安装 Turn、Task、焦点、Grant 或 `scene-restored`。等待期间会话失效时连检查点不存在/到期错误也不泄露。读取跨期限失败关闭。
- 用户显式删除事件时，由集成删除函数按相同锁序先判定受影响的已存任务来源，事务内标记 E11 删除、清除受影响 checkpoint 的明文 payload/摘要和旧幂等回执、清除相关任务来源绑定；无关事件不清掉其他任务的 checkpoint。运行角色不能直接调用旧删除或清理函数，启动时检查直接、PUBLIC、继承及 SET ROLE 权限。直接持有迁移/所有者权限者始终可以绕过候选保护，须隔离。
- 本候选采用保守限制：只支持捕获 revision 等于当前 TS 的未处理任务、无草稿和无错误。任一必需依赖无法证明时整批失败；这些限制是未开放的工程切片，不是新产品规则。存储期限目前传 null，只允许测试库使用，不能上线。

## 尚未完成、不得宣称闭环

完整恢复需要真实 Task/Turn 安装、独立来源可验证的草稿与其他自由文本、状态变化后的恢复语义、新 Session/进程的安全重签、旧 Grant/Packet/提案缓存失效，以及事务提交与实际交付之间的删除屏障。生命周期表在测试中由管理员提供合成行，真实旅行结束与关联事件续期来源未接入。自然到期时目前只阻止读取，尚无可信自动到期清理与调度；不能简单把首次记录时间当作已关联事件的最后相关交互时间。备份副本、审计及通知等清理和保留规则尚未验证。即使手动删除路径清除了当前活动数据库副本，也不证明备份或 WAL 已清理。

当前版本不能对外开放保存或恢复，也不能把只有元数据的 inspection 当作 `scene-restored`。安全发布前仍需受限角色及函数权限、正式迁移、同一最终集成 head 的真实服务和 PostgreSQL/并发/故障审查。
