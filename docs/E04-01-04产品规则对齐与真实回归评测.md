## 3. 审核阻断复现、修复与证据

| 阻断项 | 修复前复现 | 最小修复 | 本轮证据 |
| --- | --- | --- | --- |
| E04-04 回执映射与 lifecycle fail closed | 旧代码把 `submitChange` 的 `rejected`/`conflict` 统一按 success 完成；缺 `syncLifecycle` 时可能先写后成功 | `applied`→success，`pending_confirmation`→waiting_user，`rejected`/`conflict`→failed，完整原回执保留；change 在 claim/写入前要求 lifecycle 同步能力；仅真正未知才进入 reconciliation | 真实 PG：rejected/conflict 均 revision 不变且 Step/Action failed；缺同步能力时业务历史、回执、revision 零变化；applied 同步成功；pending 保持 waiting_user；未知且无回执不重提 |
| E04-01 重建所得精确期限 | 旧批次最早期限未包含每包 `built.deadline().wallMs`，来源期限跨过 final hook 时仍可能返回 | 每包重建立即保存 deadline；批次取 PacketMemory、`context.expires_at` 与 rebuilt deadline 的全体最早值，并在同一 PG 事务最终宿主复验 | 真实 PG：来源精确期限跨过 final hook，revision/runtime/Session/membership 均不变，整批仍拒绝；既有首包过期、撤权、revision、恢复换代继续通过 |
| E04-03 running Action 基础失效 | 第一步成功后 Action=running；第二步领取前 revision/runtime/TTL 失效只会 stale Step，Action 可永久 running | 无未知回执且没有正在执行 Step 时允许 `running→stale`；全部 pending Step stale，已完成结果不变 | 真实 PG：第一步 read 成功后 revision 改变，第二步 claim 返回 stale；Action=stale、第二步=stale、第一步结果完整保留；runtime 换代守卫继续通过 |
| E04-02 宿主证据与 Candidate 重入 | adapter 可自行声明不存在的 source/delivery，或把 `reentry_candidate_id=null` 隐藏 change command 指向的 excluded Candidate | object 精确 ID/version；source 仅接受可信 Packet 已有来源；delivery 在无宿主账本时 fail closed；宿主解析 change commands 推导 Candidate 目标，decide 与保存前 Gate 都复验 | 单元反例：伪造 source、delivery、object version 拒绝；真实 event source 通过；隐藏 excluded Candidate 操作被过滤且旧 Plan 保存复验失败；合法 Candidate 通过 |
| 自然到期主动脱敏 | 旧保护主要依赖 Decision read 触发；自然到期且无后续读取时 DB 原文可继续保留 | 接入既有有界 E11 maintenance：只锁取 `expires_at<=clock_timestamp()` 且 `content_available=true` 的 Decision，替换两 JSON 为既有 redacted 标记并置 false；读取兜底保留 | 真实 PG：保存独特原文、自然到期、不调用 read、执行维护后直接查库，原文消失且审计 digest/ID 保留；E11 删除和撤权测试继续通过 |

撤权不等同 E11 删除：membership 撤销立即阻断读取，但原文物理清理仍由既有 E11 删除/期限政策触发。本轮没有更改 TS/DC 权限或另立保留政策。

## 6. 遗漏与阶段复核建议

1. E04-05 未实现真实 query/calculate capability、工具调用/完成账本、result/partial/empty/timeout/error/no_service 事实强度及埃及合成交通数据。
2. E04-06 未实现 response delivery、UI presentation、feedback、改道/拒绝历史、重复提示抑制和未解决请求合法重入的持久记录。
3. E04-07 的通用 C3 fixture materializer、58 scenario＋3 walkthrough＋12 calibration 完整运行、真实模型与 UI 联测未完成。
4. 当前只接可信 `user_event`；其他 trigger 在宿主有真实登记前继续拒绝。
5. 当前 Runtime 明确只支持 Action 内 Step DAG；跨 Action DAG 在保存时拒绝，未静默进入永远等待。
6. PostgreSQL schema 仍是内部候选安装器，不是生产迁移、备份/WAL、多实例或监控验收。

阶段建议：E04-01、E04-02、E04-03、E04-04 均已具备“再次提交技术负责人复核”的本地证据条件；是否签核由技术负责人决定。E04-02 的真实语义质量及 E04-04 的用户可见完成态不应在本轮被扩大解释为 E04-05～07 已完成。
