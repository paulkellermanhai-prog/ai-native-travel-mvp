## 模型与迁移

`prisma/migrations/202610280001_trip_state_storage/migration.sql` 从空库创建四张表、索引、外键、CHECK 约束和历史防改触发器；未创建新的业务对象，原始规格快照未改。

| 模型 | 保存内容与数据库保护 |
| --- | --- |
| `TripStateDocument` | 完整原 state JSONB；tripId 主键、BigInt revision 是同一根值的索引；CHECK 强制 trip_id、schema_version、revision 一致，拒绝缺失/null。使用 BigInt 避免把原 revision 限缩为 SQL 32 位整数 |
| `TripStateHistory` | 每旅行递增 sequence；原 OperationIntent / ChangeRecord JSONB 成对保存；intentId、changeRecordId 各自按旅行唯一；CHECK 校验记录类型、旅行、意图引用及版本；UPDATE/DELETE/TRUNCATE 触发器一律拒绝 |
| `TripStateProposal` | 原待确认请求、actor、cache_key、digest、expires；proposalId 按旅行唯一；basisRevision、digest、expiresAt 与 payload 对应；数据库约束期限晚于创建且不超过五分钟；插入还检查数据库当前时刻及下一事实期限 |
| `TripStateIdempotency` | `(tripId, actorId, operationDomain, key)` 唯一；保存 requestDigest、原请求、原响应。额外保存请求正文是基础设施防碰撞措施：即使声称摘要相同，不同正文也冲突，不修改业务契约 |

日期字段为 timestamptz，持久化连接强制 UTC。真实测试曾复现 Prisma 7 适配器对非 UTC 会话产生八小时偏移；现测试库默认 Asia/Shanghai，而适配器连接使用 UTC，并通过真实期限测试，保留该回归覆盖。JSONB 内原业务时区字符串保持原样。

## 写入边界与事务

实现位于 `src/server/trip-state/internal/persistence.ts`。

- 生产只提供读存储接口，宿主仍须先完成旅行访问授权。没有 HTTP 状态写入接口，没有可用的生产 writer。
- `openSyntheticStorageHarness` 只允许 `NODE_ENV=test`、实际连接的 `antu_e02_test_*` 空库派生测试数据库，以及非 owner、非超级用户/建库/建角色/复制/绕过 RLS 身份。创建和每次写入均检查环境；生产模式下即使已有测试句柄也拒绝写。
- 该入口允许用原 Python 引擎生成的合成结果验证数据库；**parseContract / parseStateReferences 加存储一致性检查仍不等于完整业务不变量或授权**，不得将它改名包装成生产业务提交入口。
- 单一 Prisma `$transaction` 内锁定旅行行；先检查持久幂等缓存，再检查 expected_revision；因此旧版本的合法重复请求仍原样重放。相同键的摘要或正文不同返回 `IDEMPOTENCY_CONFLICT`。
- 条件更新 revision/JSONB、追加日志、插入提案和响应缓存在同一事务。行锁及 revision 条件共同阻止覆盖已提交的新版本；同旅行日志序号也在该锁内分配。
- 拟议 diff 不合并进当前 state。存储层核对记录、原请求、响应、根引用、实际 diff 与 revision 的对应；五个注入点抛错时全部回滚。
- 提案读取通过一条 SQL 同时读取当前 revision、basis 和数据库时钟；过期或 basis 已改变时拒绝用于后续确认，保留原持久记录，不自动改写用户状态。

## 迁移身份与运行身份

Prisma CLI 优先读取 `MIGRATION_DATABASE_URL`，应用连接使用单独运行身份。`scripts/prepare-storage-tests.mjs` 仅在显式测试标志、本机服务器上创建随机命名的空数据库和角色；连接信息写入 Git 外 mode 0600 文件，不输出凭证。CI 同样运行此脚本，不使用生产环境。

迁移 owner 持有表/函数及 DDL 权限。测试运行身份无任何超级权限：Doc 只允许 SELECT/INSERT 和 UPDATE(revision,snapshot)；其余三表只允许 SELECT/INSERT；无 CREATE、历史改写、TRUNCATE、触发器管理、迁移表改写或 tripId 更新权限。历史触发器还阻止 owner 的普通改写 DML；可信 DBA/迁移 owner 仍可通过 DDL 改变保护，因此这不宣称抵抗恶意超级管理员。

## 规格 → 实现 → 真实数据库用例

测试：`tests/trip-state/persistence.integration.test.ts`；来源为原 `SPECIFICATION.md` §2、5.1、5.2，`HISTORY_FINAL.md` 及 Python `engine.py:Store`。合成快照/日志由 `tests/support/storage-fixtures.py` 调用未修改的原 Python 引擎生成，不实现一套假命令结果。

| 要求 | 实现位置 | 实际覆盖 |
| --- | --- | --- |
| 空库迁移与版本一致 | migration、Document CHECK | 迁移前 0 表、再部署；绕过适配器直接写不一致 revision/trip/schema/null 均拒绝；超 32 位 revision 可往返 |
| 真实保存与追加历史 | `commitSyntheticBatch` 的四表事务 | 原场景 A 七步结果逐步保存/读回，完整 intent/change 及顺序匹配。仅测试存储，不宣称 E02-03 命令引擎已实现 |
| 并发与幂等 | FOR UPDATE、CAS、复合唯一键 | 两个独立连接竞争，仅一笔提交；同键并发一笔提交一笔重放；过期 revision 重放先于冲突；同摘要异正文拒绝；跨旅行同 ID/键隔离 |
| 提案基础 | Proposal 约束、pending 查询 | 原 pending 结果保存且 state 不变；唯一性失败回滚；过期、超五分钟、晚于事实期限拒绝；真实流逝后读取过期；basis 改变拒绝 |
| 原子性和异常 | 事务失败 seam、唯一约束 | applied/pending 各五个位置注入失败，四表检查无半写；日志重复和提案重复在写入中途失败时回滚 |
| 不可变性与身份 | GRANT、CHECK、历史触发器 | 实际运行账号不能改/删/清空历史、禁用触发器、创建表、改迁移记录、改 tripId、延长期限或重写幂等摘要；迁移身份的历史改写 DML 也拒绝 |
| 进程恢复与崩溃 | 独立 Node/pg 进程、新 Prisma 连接 | 写入后断连，独立 PID 读回 state/history/proposal/cache，再连接重放；另一个进程在真实 UPDATE+INSERT 后、COMMIT 前被 SIGKILL，数据全部回滚 |
| 生产边界 | 测试入口和实际身份检查 | owner 连接拒绝；生产环境不能创建 writer，也不能使用已有测试句柄写入；应用路由无新增写接口 |

本地使用 PostgreSQL **17.10** 隔离二进制、SCRAM、0700 私有 Unix socket、不开放 TCP。干净源代码目录执行完整 check：**299 测试通过、0 失败、0 跳过**，其中 32 项存储测试；原 E02-01 / Python oracle 均保留。安装、Prisma、TypeScript、零警告 Lint、Build 通过。最新版 GitHub CI 使用 `postgres:17`，实际版本与最终结果以本 PR 最新 head 的日志为准。

## 复现与下一阶段要求

使用本机/CI 的**可丢弃 PostgreSQL 17 测试实例**，先安装项目及原 oracle 依赖，再通过环境提供迁移连接：

```sh
npm ci
npm run db:generate
E02_TEST_PROVISION=1 node scripts/prepare-storage-tests.mjs /private/tmp/e02-storage-new.json
```

上例读取环境中的 `MIGRATION_DATABASE_URL`。生成文件不能入库；CI 自动将其路径设置为 `E02_STORAGE_ENV_FILE`、运行连接设置为 `DATABASE_URL`，并安装和设置 `TRIP_STATE_PYTHON`，随后执行完整检查。Mac 的原 iCloud 缓存限制仍以一次性干净源代码目录隔离；此目录不构成第二套工程。

后续必须接入真实宿主认证/旅行授权、完整命令与语义守卫，才能新增经审核的生产写能力，不能仅取消测试模式开关。确认提案的消费、原提交缓存最终响应更新、拒绝/确认命令、调度与清理策略仍属于后续切片；当前运行权限刻意不允许删除提案或更新响应缓存，接入时需审查相应最小权限迁移。没有实现这些业务行为，也未启动 DC/NAP、自然语言抽取或 E02-03。
