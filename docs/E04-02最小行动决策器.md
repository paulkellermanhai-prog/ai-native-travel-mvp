# E04-02｜最小行动决策器

状态：本地实现与定向验证完成，等待技术负责人签核；不自行记为 E04-02 ACCEPTED。

## 增量边界

- `decide()` 只消费 E04-01 构建的可信 `DecisionRequest`，复验 `user_event`、Packet 期限、完整正文和事件引用，不写 TS、DC 或 NAP 运行记录。
- 编排顺序固定为 G01 当前请求 → G03 语义候选 → G02 宿主资格检查 → G03/G04 主行动和最多两个可并行准备选择。
- 语义适配器只提供回应、候选、简短理由和排序；宿主校验 Packet/Task/完整交付、必需对象、假设分支、冲突 OpenIssue 和 Candidate 重入边界，并逐包复制 basis。
- `reevaluate()` 只对新可信事件重新运行语义与资格竞争，不沿用旧 Action。
- 无合法输入、过期 Packet 或不合法语义结果返回明确错误；直接回答可以输出空 `actions`。

## 行为证据

| 正式案例 | 本轮断言 | 边界 |
| --- | --- | --- |
| S03 | “阿斯旺值得加吗，我担心转场”选 D3 主回应，可并行 D2 低风险读取准备 | 未覆盖的疲劳保持未知，不写硬阈值 |
| N05 / C12 | 可靠交通事实冲突时仅列明冲突或复核 | 带 `change` 的候选无资格，不把冲突当已解决 |
| F04-A | 假设分支可比较 | 任何 `change` 候选无资格 |
| X03 / X05 | 用户主动重开时可响应只读探索 | 已排除 Candidate 不因旧入口自动重入 |
| J12 | 实质回答时可无额外行动 | 不制造新推荐或用户完成确认 |

定向 Vitest 30/30、TypeScript 与 ESLint 通过。这些确定性语义夹具只证明编排与安全 Gate，不代表真实模型质量。
