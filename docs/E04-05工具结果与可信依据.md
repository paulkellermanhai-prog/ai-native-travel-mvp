## 1. 实现边界

- `tool-capabilities.ts` 是可信宿主固定注册表；只开放 `egypt-transport-synthetic-v1` 的只读 HTTP query 和 `egypt-cost-subtotal-v1` 的确定性 calculate。能力、provider、参数结构、超时和事实等级不能由模型动态声明。
- `002-tool-results.sql`、`tool-runtime-store.ts` 保存不可变调用与完成绑定，关联 owner、Trip、workspace、runtime、Decision、Action、Step、capability、provider、查询摘要、basis revision、结果状态和当前可用性。
- `tool-dispatch.ts` 在原 Action/Step 认领后执行工具；交通观察只以 Tool actor 经 E02 `ingest_fact` 写入，NAP 账本不成为第二份旅行事实。明确的事实写入拒绝不会被记成成功或当前可用。
- 结果状态保持 `result/partial/empty/timeout/error/no_service` 六分；timeout/empty 不提升为 no_service，分项费用不提升为全程预算。
- 晚到、重复 dispatch、revision 改变、runtime/Session/membership 失效、查询条件改变和结果 TTL 到期均不能继续支持当前判断；历史回执仍保留。
- `tool_result/state_change` 必须由完成账本证明；未注册 trigger 继续 fail closed。G05 产生新 DecisionPlan，不原位复活旧 Action。
- 合成交通响应明确带 `synthetic:true`，不表示真实班次、票价、可预订性或供应商接入。

## 2. 埃及案例证据

| 案例 | 实际链路 | 断言结果 |
|---|---|---|
| A 完整交通查询 | 真实 Session → Packet → Plan → Step claim → 本地 HTTP → ToolCompletion → E02 Tool observation → PG | `result` 与日期/路线/provider 绑定；ExternalFact 由 E02 权威事务写入 |
| B 部分费用 | calculate Step → 确定性 subtotal → completion ledger | `partial`；缺住宿和餐饮；`is_full_trip_total=false`；不写伪造总预算事实 |
| C 超时和空结果 | 同一受控 HTTP 适配器分别返回/触发 empty、timeout、no_service | 三种记录严格不同；只有明确 no_service 形成 absence observation；timeout 触发重评后保持未知 |
| D 条件改变 | 11 月 14 日查询后，经原 E03 write-bridge/E02 User change 改为 11 月 16 日 | 旧 pending Action/Step stale；新查询 digest 不同；旧结果不支持新日期 |
| E 晚到和重复 | 工具等待期间由可信 Tool 写入并增加 TS revision；已完成 Action 再 dispatch | 晚到 completion `current_usable=false`，Action/Step stale；重复 dispatch 返回原记录且 HTTP 调用数不增加 |
| F 权限失效 | 工具执行中删除 membership | 完成记录和业务写入均不产生；旧 Action 不能继续执行 |
| 结果自然过期 | 短 TTL 交通 observation 到期后创建当前 Packet 并尝试 tool_result trigger | 可信触发拒绝；旧完成只保留历史，不支持当前 Plan |
| G05 可信重评 | tool_result 与含 validated fact 的 state_change 从宿主完成账本读取 | 伪造 completion 被拒绝；真实 trigger 生成并保存新 Plan，不伪造 user_event |
