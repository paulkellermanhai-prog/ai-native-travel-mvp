## 已实现与限制

- `write-bridge/rules.ts`：在原 change/packet/confirm 合同内检查轮次、当前事件、版本、恢复后只读、假设分支、重要动作完整交付、Grant 字段和确认提案绑定。它是纯规则，不制造或验证 Session、Grant 真伪、当前 Packet 或实际交付。
- `write-bridge/orchestrator.ts`：在宿主事务回调内处理受权写入，精确相同运行请求的持久回执重放、键冲突、无 Grant 的 Model 路径、匹配真实宿主 Grant 的 User 路径，以及本轮提案确认。Host 接口仅为待集成契约；**当前没有实现能提供这些保证的真实 host，因此整条写桥未接线，不可直接用于生产**。
- `write-bridge/ts-adapter.ts`：仅封装现有 Session 用户与签名 Model 两个真实 TS 命令通道，复用其现有认证、PG 事务和关停。这个低层能力不证明 Event、Task、Packet、Grant 或完整交付，也不能独自作为 DC 写桥调用入口。
- `http-adapter/handler.ts`、`http-core/response.ts`：实现 R6 列出的 POST 合同解析、响应校验、来源和媒体类型限制、保密错误映射及未实现端点关闭。只转发 Cookie 到宿主、未知端点不调用业务操作；没有挂载到生产公开路由。宿主注入操作必须自行完成真实认证、归属与事务检查；不把测试桩当成真实服务。
- `tests/http/e03-runtime/adapter.test.ts` 在环回地址使用真实 TCP socket，宿主及身份是合成的。真实 socket 只证明网络传输与适配器行为；不是实际 Session、PG 或完整 07 联测。

## 需要主工程提供的最小真实接口

`TransactionalBridgeHost.change` 需在当前真实 Session/旅行授权和同一可信运行代次中，取到实际 Turn、Task、当前 Packet、已交付集合、原事件和不可伪造的精确 Grant；业务写的事务内须复验权限、Packet/版本与其他必要条件。宿主必须保证本轮运行幂等键、整个请求摘要及 TS 原幂等结果一致，并在响应丢失或跨事务故障时不声称已确定提交、不得重放业务命令。现有 `openTripCommandService` 的 `guard` 可在 TS 事务里复验 Session/TripMembership，但没有暴露上述运行级 Packet／Grant 状态的同事务接口；不能用事务外读取加盲写声称已闭合。确认入口还需可证明的本轮真实用户确认及原 Proposal 绑定；缺任一项相关连接点关闭。

07 需主工程将具体已可用服务通过真实宿主操作安装到隔离测试环境，校验 Session/PG/HTTP，再按实际服务逐个接入；不可把 synthetic host 标成可信服务。收到共享接口时按单一集成 head 重新做跨用户、权限撤回、旧 Grant、同键并发、事实争议及异常原子性测试。保存/恢复和 E11 可分别在其真实能力可用后连接，不要求其他整个阶段先验收。
