# E03-02｜C12 条件注释语义差异：技术裁定材料

## 待裁定事项

在以下合成对照中，事实 A 的 `service_exists=true`，偏好条件为 `eq(A./value/service_exists, true)`，其目标范围适用；完整状态中未选入正文的事实 B 与 A 具有相同范围且服务结论相反。固定 R6 参考与当前受控候选对该偏好 `applicability` 的结果不同，需由原工程计划的技术负责人明确选择并记录；本材料不视为批准或产品决定。

| 同一快照与条件 | 固定 R6 注释 | 当前候选注释 |
| --- | --- | --- |
| B 不存在／不构成争议 | `applicable` | `applicable` |
| B 构成争议但未进入选中正文 | `applicable` | `unknown` |
| A、B 均选入且构成争议 | `unknown` | `unknown` |

复合条件对照使用同一未选中 B 争议场景：`not(A)` 为 R6 `not_applicable`、候选 `unknown`；`all(A, true)` 和 `any(A, false)` 为 R6 `applicable`、候选 `unknown`；`all(A, false)` 两者均为 `not_applicable`，`any(A, true)` 两者均为 `applicable`。后三值逻辑中有决定性分支时，未必改变最终 applicability。

差异来自条件求值的可见对象：R6 `Runtime._annotations` 使用选中对象映射；候选在同一选中正文上额外传入完整快照的 C12 争议集合。两种路径的 `Store.context` 仍使用全状态识别争议并将已选 A 记入 `stale_fact_ids`；此对照不意味着 R6 将 A 标成可靠事实，也不扩大选中正文。

## 影响和选择

- **保持 R6 原样：** 条件注释严格使用选中对象；下游看到 `applicable` 与事实 A 的争议／stale 标记，必须同时处理两者。恢复此路径涉及移除候选对完整争议集合的条件传参，再重跑联合验证。
- **接受候选的限定差异：** 条件注释在完整快照存在未选中反事实时保守返回 `unknown`；冲突解除后可恢复 `applicable`。这改变下游可观察字段，不改变事实正文、事实可信度、业务状态或权限，不代表已经决定页面展示、对外承诺或后续行为。

这些选项均应由技术负责人结合既有 C12 规则裁定。若该字段实际驱动新的面向用户展示、产品承诺或其他产品取舍，应另提交 Owner；当前没有证据证明已作出或必须由本任务作出此类决定。
