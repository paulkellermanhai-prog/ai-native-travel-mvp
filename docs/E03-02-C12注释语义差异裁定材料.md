# E03-02｜C12 条件注释语义差异：裁定与证据

## 已裁定事项

在以下合成对照中，事实 A 的 `service_exists=true`，偏好条件为 `eq(A./value/service_exists, true)`，其目标范围适用；完整状态中未选入正文的事实 B 与 A 具有相同范围且服务结论相反。固定 R6 参考与当前受控候选对该偏好 `applicability` 的结果不同，已由原工程计划 AI 技术负责人以 `E03-02-C12-APPLICABILITY-2026-11-06-01` 接受候选的限定工程语义；实现最终证据仍待审核，不构成阶段 PASS。详细来源和范围见 [e03-02-c12-applicability-acceptance.json](e03-02-c12-applicability-acceptance.json)。

| 同一快照与条件 | 固定 R6 注释 | 当前候选注释 |
| --- | --- | --- |
| B 不存在／不构成争议 | `applicable` | `applicable` |
| B 构成争议但未进入选中正文 | `applicable` | `unknown` |
| A、B 均选入且构成争议 | `unknown` | `unknown` |

复合条件对照使用同一未选中 B 争议场景：`not(A)` 为 R6 `not_applicable`、候选 `unknown`；`all(A, true)` 和 `any(A, false)` 为 R6 `applicable`、候选 `unknown`；`all(A, false)` 两者均为 `not_applicable`，`any(A, true)` 两者均为 `applicable`。三值逻辑中有决定性分支时，未必改变最终 applicability。

差异来自条件求值的可见对象：R6 `Runtime._annotations` 使用选中对象映射；候选在同一选中正文上额外传入完整快照的 C12 争议集合。两种路径的 `Store.context` 仍使用全状态识别争议并将已选 A 记入 `stale_fact_ids`；此对照不意味着 R6 将 A 标成可靠事实，也不扩大选中正文。

## 影响和选择

- **保持 R6 原样：** 条件注释严格使用选中对象；下游看到 `applicable` 与事实 A 的争议／stale 标记，必须同时处理两者。恢复此路径涉及移除候选对完整争议集合的条件传参，再重跑联合验证。
- **接受候选的限定差异：** 引用被争议事实的原子条件返回 `unknown`；复合条件仍按原三值逻辑，最终 applicability 仍受原 scope 约束。当前示例中冲突解除后可恢复 `applicable`。这改变下游可观察字段，不改变事实正文、事实可信度、业务状态或权限，不代表已经决定页面展示、对外承诺或后续行为。

技术负责人已选择并接受第二项的限定语义；第一项作为真实旧参考的对照保留，不能静默改写。若该字段实际驱动新的面向用户展示、产品承诺或其他产品取舍，应另提交 Owner；当前没有证据证明已作出或必须由本任务作出此类决定。

## 直接证据和时效边界

`scripts/e03-02-annotation-oracle.py` 校验固定 R6 文件及 TS 阶段 A 哈希，直接调用锁定 `Runtime._annotations` 与 `Store.context`；`tests/decision-context/c12-reference.test.ts` 用相同快照比较 R6 和 TS 候选的完整 Context（仅排除两者各自产生的随机 ID）、完整注释及两类争议选择；在 CI 保留合成输入与两边真实输出的附件，不含用户数据。`tests/decision-context/c12-scope.test.ts` 记录 scope 和不可比事实边界；`tests/decision-context/c12-temporal.test.ts` 单独覆盖复合条件与未选中 B 的到期／生效；旧组装在 state revision 不变但争议状态变化后需消费复验，不得仅以版本相等放行。合成时间对照中，B 到期或达到 observed_at 后，若争议及已选证据确实改变，旧组装报 `EVIDENCE_CHANGED`，重新组装才给出对应新值；若其他有效事实仍使争议持续或变化事实不可比，旧组装可继续消费。未来 observed_at 仅为边界测试，不代表生产允许导入未来事实。
