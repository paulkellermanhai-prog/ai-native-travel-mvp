# E03-02 授权失败路径复核修订

依据独立审核任务 01a1af8d-c1cb-7423-8dba-ecda4ccaf01f 对 PR #15 原 head 895d1dd 的结论：初始授权后成员撤权或会话过期时，提交前解析和 submit/confirm 的异常分支可能读取或返回当前 revision。原审核结论为不通过；本修订提交后仍须重新审核，不能视作已接受。

- submit 和 confirm 在初始授权后解析输入；提交/确认事务先仅锁定 trip 标识，再重新验证授权，之后才读取状态、版本和幂等结果。锁顺序维持原有并发保护。
- 权限失败统一返回 PERMISSION、revision 0 和空变更；其他已知错误要在新的受保护读取事务中重新授权后才能返回当前 revision。重新验证不可用时返回中性版本；HTTP 适配层异常同样不携带先前读到的版本。
- 真实 Session/PostgreSQL 测试设置 A 初始授权后暂停，由另一有效成员 B 推进版本，再撤销 A 的成员资格或使其会话过期，覆盖 submit、confirm、二者幂等重放与输入解析失败，并比较四张业务表的内容以证明无额外写入。HTTP 另覆盖流式请求与撤权交叠。被授权时的错误合同与当前版本也有对照。
- 与固定 R6 Python 原包对照多层引用闭合及相关规则，包括原规则不遍历 OpenIssue.evidence_ids；不将 UX-02 R7 候选或 Python Oracle 当作已获批准的 TS 应用实现。

E03-02 仍处于开发及复审中。真实认证下 TS 业务读取仍须公共认证修订通过增量复核、TS 应用实际提交获技术接受并纳入工程、以及同一集成 head 联合验证；PR #11 尚未满足这些条件。本修订未合并或部署，也未放行后续阶段。
