实际阅读与核对范围：用户四项所指的总纲 V2、PRD、机制交接和 Schema 包相关正式文档；补充 Trip State 交接、Problem 路径文档；正式字段、共享结构、关系、生命周期、转换、传播、权限、历史、不变量、场景、验证、评审和包导览；对照 Context 请求/对象机器合同、运行组装和有效性检查代码及相关测试。历史机会/聊天归档仅用于相关段落追溯，不提升为正式合同。

这里不声称逐个重读了全部重复 JSON 样例、全部代码行，或复跑了整个验证脚本。完整主资料阅读发生于本任务的资料/计划阶段，执行阶段再次核对关键段落、文件指纹和实现。

### 1.1 权威顺序不是统一的“新文档优先”

1. 当前用户任务规定本轮范围与交付边界；用户明确补充 U02 澄清探索阶段的决策语义。
2. 业务产品原则以总纲 V2 为主；PRD 的明确首版要求及正式 Schema 中已确认的收口关系，覆盖历史未定项。
3. 字段、对象、权限、传播与状态转换以 Trip State 0.1.0 正式工程规格及 Final 配套为开发约束。旧交接中的候选枚举不与其平权。
4. 实现与测试用于说明现有覆盖和偏差，不能静默改写正式产品语义；声明态与已实现入口不同要标明。
5. 历史思考和评审解释来源，不将被替代方案重新引入。

现有文件自称“工程契约定稿”“Ready for V1 Review”。本轮按用户明确指示将其作为继承基线；未获得独立人工签字记录，不能额外声称存在该记录。Ready for V1 Review 不等于生产就绪。
