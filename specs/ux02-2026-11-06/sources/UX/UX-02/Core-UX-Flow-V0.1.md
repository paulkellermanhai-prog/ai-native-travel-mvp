# Core UX Flow V0.1｜ANTU UX-02

> 状态：**UX-02 V0.1 设计规格已获 Owner 验收（2026-11-05）**。本文件整理已讨论的产品行为；早期 UX-02 原 Chat 未完整取回。文中“底稿支持”表示可追溯至用户提供的设计知识底稿，不等于已复核原始 Owner 裁决。证据分级见 [README](README.md)。

## 0. 共同约束与读法

F1–F6 是需求覆盖和验证单元，不是必须线性走完的六页向导。用户可从对话、地图、时间轴、方案比较进入或改道；跨 Flow 始终共享同一权威旅行状态。浏览、兴趣、候选、假设、编辑草稿、已采用方案、事实核验分别有不同含义。AI 可以准备信息、候选和修复，但不得替用户作重要价值取舍、放宽硬约束或把未知事实写成已核验。[UX-01](../UX-01/Flow-Coverage-Matrix-V0.1.md)；[PRD](../../AI%20Native旅行产品｜PRD%20V0.1.md) §3、§4；[KB-08](sources/KB-08.md) §8.2–8.5。

以下“采用／确认”只针对**已向用户呈现的对象、版本、影响范围和未知事项**。用户明确指令可以是合法授权，不必再弹泛化确认；发现此前未呈现的重要牺牲时，需要新的具体裁决。保存采用决定不表示交通班次、库存或全程预算已核验。[KB-03](sources/KB-03.md) §3.6；[KB-06](sources/KB-06.md) §6.3–6.4；[NAP](../../Next-Action-Policy-V0.1/policy/behavior-spec.md) P02。

| 横向对象 | 作用 | 不得推导 |
|---|---|---|
| 旅行业务状态 | 目标、条件、偏好、候选、事实、骨架、决定、问题及历史 | 页面焦点或模型措辞不自动改写它 |
| 当前任务上下文 | 本轮目标、焦点、比较对象、缺口和暂缓事项 | 不成为第二份有效旅行 |
| 编辑草稿 | 累积尚未采用的操作，绑定基础版本 | 不因浏览、假设或跨页切换自动提交 |
| 假设预览 | 在明确基准上计算“如果怎样” | 不自动覆盖草稿或有效方案 |
| 事实／计算结果 | 有来源、条件、时效、覆盖范围和未知 | 查询失败、空集、估算不升级为无服务或指定日期已证实 |
| 历史版本 | 可回顾的已保存规划演化 | 查看不等于恢复；恢复要产生当前条件下的新版本 |

## F1｜意愿启动与探索

**目标和入口。** 用户只说想去埃及，或从 F2/F3/F4 回来补充认知，或跨会话继续探索。系统用有限目的地地图、城市差异和**具体体验**建立空间与内容参照；日期、预算未给出也能开始。F1 不以看完卡片为通关条件。[KB-01](sources/KB-01.md) §1.1–1.3；PRD-001／A01。

| 步骤 | 用户动作与可见反馈 | AI／系统动作与状态 |
|---|---|---|
| F1-S01–02 启动 | 表达目的地意愿；看到地图、代表城市与简短介绍 | 建立/读取旅行目标，标明已知条件；不强制问卷，不自动生成已确认骨架 |
| F1-S03 城市聚焦 | 点击地图城市；看到城市及差异信息 | 更新**查看焦点**和相关内容；不把点击写成“决定去该城市”；对话中正在处理的另一城市任务继续绑定原对象 |
| F1-S04–06 体验探索 | 查看单项体验卡、滑动反馈或展开详情后返回原位置 | 浏览、详情查看、明确喜欢、排斥分别记录；反馈以体验为对象且带条件，右滑不确认城市，点击不算喜欢；已反馈内容可回看纠错 |
| F1-S07 条件性表达 | 说“喜欢历史，但怕转场累” | 同时保留兴趣与顾虑；不得推成硬性的转场次数/小时阈值；后续分析要使用原范围与条件 |
| F1-S08 连接探索 | 点击两城连接或交通方式卡 | 展示这段连接的概略方式、耗时、费用口径、来源与未知；对某段交通的拒绝不扩成全局交通偏好；地图连线不证明真实班次 |
| F1-S09 检查点 | 一批体验后可继续当前城市、看其他城市或了解代价 | 仅在有增量价值时轻量提示；“约四张”、固定三按钮都不是批准阈值/控件 |
| F1-S10–11 连续性 | 跨城市切换、返回详情、再次点击城市 | 恢复浏览进度；已反馈对象可追溯，未浏览内容可重排；介绍可复用，条件实变时才更新；异步结果必须绑定原城市/请求 |
| F1-S12 转向 | 直接要求比较、暂停或继续探索 | 尊重直接请求，进入 F2/F3；不强制完成探索；暂停保留工作，恢复时以最后成功保存点为准 |

**分支和失败。** 用户先排除后重新询问，仅表示重新探索，不自动撤销负面反馈或合法候选排除；明确纠错才更新相应有效判断并保留历史。交通查询超时显示未知，不写“无服务”；返回详情不得重置进度。编辑中的探索只改变查看焦点，不能静默改草稿或已采用旅行。底稿中的左右滑是已讨论操作，最终控件仍待 UX-04 验证。[KB-01](sources/KB-01.md) §1.4、§1.7–1.8。

## F2｜决策缺口推荐与改道

**目标和触发。** F2 识别当前阻碍用户判断的缺口，选择下一步有价值的帮助。触发包括明确冲突、跨城市探索已积累有意义反馈、用户直接要求比较／规划；它不是固定页面，也不按浏览张数推进。缺口可能是差异认知、时间/资源取舍、现实代价、价值优先级或系统理解错误；多个缺口同时存在时优先服务眼前任务。[KB-02](sources/KB-02.md) §2.2–2.4；PRD-003／A03；NAP-P04。

| 步骤 | 用户动作与可见反馈 | AI／系统动作与状态 |
|---|---|---|
| F2-S01–03 定位 | 表达“卢克索不错但怕折腾”；收到与此问题相关的回应 | 结合前文确认目标、条件与顾虑，判断交通代价是否真影响当前决定；缺字段本身不等于缺口 |
| F2-S04–06 准备和建议 | 看到有依据的交通/体验分析与可选行动 | 条件和工具足够时主动查、算、整理；区分已知、估算、未知和失败；解释收益与代价；推荐入口讲清原因但不占用其他常驻入口 |
| F2-S07–08 接受／跳过／改道 | 选择比较、继续探索、改用地图或暂停 | 接纳新目标，旧推荐退出突出态；保留有效状态和未解决问题；不反复催促，也不把沉默当同意 |
| F2-S09–13 探索成熟 | 看到 AI 先做的轻量总结，再自行选下一步 | 总结明确兴趣、顾虑、城市差异、未解决取舍；推测与用户明说分开；不中断正在进行的明确任务，不以固定卡数触发 |
| F2→F3 直接规划 | 说“帮我安排／比较” | 采用底稿中的方案 C：先识别关键取舍，必要时最小提问或声明假设，尽快给具体可比候选；不以问卷阻断，也不在信息不足时虚构完整可执行行程 |

**行动边界。** AI 的后台准备和向用户推送是两回事；事实核验按当前决定的重要性、可信来源和已知条件分层。未响应不等于任务完成；答复交付、行动成功、用户决定是三件事。用户拒绝按对象和条件生效，后续主动重开仍须满足当前重入规则。[KB-02](sources/KB-02.md) §2.7–2.11；[NAP](../../Next-Action-Policy-V0.1/policy/behavior-spec.md) P03/R01/R03。

## F3｜骨架比较与取舍

**目标和入口。** 用户主动要方案、F2 判断比较有价值、F4 编辑后回到比较、或查看/恢复历史。骨架聚焦城市组合、顺序、停留和主要连接；默认可比较两项有**实质差异**的候选，但无有效差异时不凑数。日期未给出仍可做条件化比较，硬约束冲突则说明无解。[KB-03](sources/KB-03.md) §3.1–3.5；PRD-004／A04。

| 步骤 | 用户动作与可见反馈 | AI／系统动作与状态 |
|---|---|---|
| F3-S01–03 请求与读取 | 提出规划目标；必要时回答一个真正阻断判断的问题 | 读取当前权威旅行和任务上下文，区分硬约束、弹性意向、顾虑、未知；旧日期事实不能当新日期依据 |
| F3-S04–06 候选与校验 | 看到可比较的候选 | 生成不同旅行策略，检查结构、硬约束、可核验事实及整趟连锁影响；费用只按同币种/人数/范围的有据分项比较；未知不补零 |
| F3-S07–09 比较与建议 | 比较获得、保留、放弃的体验，以及时间、转场、费用、可行性和未知；可追问/都不选 | AI 可解释推荐，但不以单一不透明评分替代用户判断；查看、展开和假设都不构成采用 |
| F3-S10–12 明确采用 | 点击明确“采用 B”或说“就按 B”；看到当前采用范围和待核验事项 | 对当前版本与已展示影响执行权限/约束/事实守卫；无新重大取舍时该操作本身表达确认，不重复普通确认；合法采用生成当前有效版本及历史；返回 F1/F4 不丢决定 |
| 历史回顾 | 查看旧版、与当前版比较 | 旧版只读展示，不把旧事实的 verified 结论延续到现在 |
| 整份恢复 | 明确要求恢复旧方案 | 以旧内容为候选，按当前约束/事实/未知重新预览并生成**新版本**；保留从旧版到现在的历史 |
| 城市级恢复 | 仅恢复某城旧安排 | 明确目标城市和基准版本，预览对相邻连接、总天数、费用、其他城市及已确认体验的影响；不无意回滚全程 |

**冲突保护。** 已知硬冲突阻止错误采用；未知只能按当前可确认范围呈现。AI 可提出多个最小牺牲修复，不能为消除局部冲突自动删掉其他已确认核心体验。版本历史、整份和城市级恢复是底稿记载的后期 UX 成果；Owner 于 2026-11-05 在本 Chat 明确两种恢复均须在 MVP 开发。现行 PRD 尚待同步，工程能力见工程矩阵。[KB-03](sources/KB-03.md) §3.6–3.11；[KB-09](sources/KB-09.md) §9.4、§9.13。

## F4｜地图与时间轴编辑

**目标与工作空间。** 顶部横向时间轴、左／中央主地图、较窄右侧上下文区、地图内城市浮层和可用的 AI 对话入口协作。浏览城市与真正编辑分开；地图、时间轴、明确自然语言修改操作的是同一份**编辑草稿**，其基础是当前有效骨架。[KB-04](sources/KB-04.md) §4.3–4.8；PRD-005／A05。

| 阶段 | 用户动作与反馈 | AI／系统动作与状态 |
|---|---|---|
| 进入和聚焦 | 从有效方案、地图内容或时间轴进入编辑；右侧可看整趟或城市摘要 | 进入编辑会话时绑定旅行、基础版本及编辑目标；切换信息焦点不等于切换修改目标，也不结束编辑 |
| 连续操作 | 调整顺序、停留、连接；地图与时间轴即时同步 | 多项操作累计到一份未提交草稿并留操作来源；有效版保持；普通动作可直接编辑，不逐项弹全面分析或确认 |
| 即时反馈 | 看到确定性的结构变化、轻量修改记录及就地重要风险 | 能直接算的夜数/顺序即时更新；需事实工具或复杂影响的结果标待算/未知；重要决定或硬约束影响及时提示但允许继续安全编辑 |
| AI 对话编辑 | 明确说“卢克索多一晚”；或只问“这样会不会太累？” | 前者在对象与授权明确时作用于同一草稿；后者是分析，不自动改；异步回答绑定发起时的对象与版本 |
| 完成编辑 | 点击“完成编辑” | 固定整组改动、核对基础版本、做结构与已知硬约束检查、整趟影响分析和可完成的事实核验；若没有新未授权重大取舍，按合法意图生成新有效版本；否则保留草稿与旧有效版并请求具体裁决 |
| 撤销／放弃／暂停 | 撤销单项、明确放弃本会话，或暂离页面 | 三者语义分开；放弃草稿不动有效版；暂停/跨页/跨会话尽量恢复最后成功保存的工作位置，未确认保存应提示 |
| 失败与并发 | 保存失败、完成编辑超时或基础版本已变 | 不报虚假成功/失败；核实权威业务结果和原幂等回执；旧草稿不覆盖新版本，保留用户编辑成果供重新协调 |

**日期与冲突。** 无日期时仍可完成当前层次的结构和价值决定，但具体班次/库存保持未知。草稿冲突与有效版冲突分开；已知冲突在相关地图、时间轴和信息区持续可见，AI 可准备修复而不越权应用。[KB-04](sources/KB-04.md) §4.10–4.15；PRD-007/008。

## F5｜假设、纠错与有限重算

**目标与语义。** “如果不去阿斯旺”是推演，“改成不去”是修改；“刚才说错了”可能是在纠正原操作而非再执行一次。A=当前有效版，B=未提交编辑草稿，C=有明确基准的假设预览；A/B/C 只是解释代号，不要求新增同名 Schema 状态。F5 复用现有工作空间，不另建默认 What-if 页面。[KB-05](sources/KB-05.md) §5.1–5.3；PRD-002/006／A02/A06。

| 步骤 | 用户动作与反馈 | AI／系统动作与状态 |
|---|---|---|
| F5-S01–03 假设定位 | 提出“如果怎样”；看到假设标签与基准 | 判断当前基准是 A、B 或指定历史版；对象不明且后果重要才最小澄清；生成隔离的 C，不改 A/B |
| F5-S04–06 影响分析 | 比较 C 与基准，看到体验得失、停留、连接、费用口径、约束、未知 | 先识别依赖和受影响范围再计算；必要时扩大全程，不任意改无关决定；AI 可给依据清楚的建议 |
| F5-S07–09 继续／放弃／采用 | 继续追问、保留原版或明确采用 C | 继续追问保留基准关系；放弃 C 不等于拒绝原旅行；编辑中采用 C 才进入 B，编辑外按合法修改/采用产生新有效版本 |
| F5-S10–16 编辑中假设 | 在 B 上试一个改动，再决定是否纳入 | C 基于 B，差异相对 B 展示；查看 C 不覆盖 B；纳入后仍只是 B 的一部分，需完成编辑才可能替换 A |
| 多轮假设 | 连续比较 C1/C2 或把某个假设作为新基准 | 明示每次基准和版本，避免把连续假设误当累计修改；不要求每个临时推演都生成正式历史版本 |
| 纠错 | 更正尚未执行指令、草稿操作、已确认选择、偏好理解或旧事实 | 识别被纠正对象、范围与状态；未执行可改解释，草稿操作需撤/改原意图，已确认决定走新授权版本，偏好纠错不自动改行程，事实变化走来源与重核验 |
| 条件变化 | 日期、预算或外部事实变化 | 传播相关依赖，标记旧依据陈旧，局部重算/重核验；已确认价值选择保持，确需改变时向用户交代取舍 |

**授权与失败。** AI 不得用“最优修复”静默牺牲已确认体验；工具失败留住 A/B/C 的合法成果，未完成范围标未知。历史查看与恢复属 F3/F6 的明确操作，不能由 F5 的假设自动触发。[KB-05](sources/KB-05.md) §5.6–5.13。

## F6｜关键确认、保存与回顾

**目标。** 让用户知道“我决定了什么”“哪些事实已核验到什么程度”“什么仍要处理”。规划决定和现实核验是两个维度；骨架被采用不等于班次存在、可购买或总预算完整。确认对象与范围可以是骨架，也可以是已知影响的具体修改；不把 L1/L2/L3 规划深度分析框架变成三个强制确认关卡。[KB-06](sources/KB-06.md) §6.3–6.6；PRD-008／A08。

| 路径 | 用户动作与可见反馈 | AI／系统动作与状态 |
|---|---|---|
| F6-S01–07 无日期采用 | 查看候选得失，明确采用骨架；看到采用内容和待核验事项 | 检查对象/版本、已知硬约束、已展示影响及授权；可保存当前层次的决定，未知日期相关事实仍未知；需要新重要裁决时保留旧有效版 |
| F6-S08–15 后加日期 | 提供日期和时间；看到受影响连接、体验和冲突定位 | 保存明确条件，找出依赖旧/未知日期的结果并查询可信来源；已知冲突、旧事实过期与未查询分开；只重核验受影响范围；AI 准备修复，重要牺牲交还用户 |
| F6-S16–23 完成编辑 | 用户提交一组草稿，或拒绝新牺牲 | 核对基础版本，聚合校验；普通范围合法则产生新有效版；未授权重大影响/已知硬冲突保留草稿和旧版；仅有待核验事项可按其真实范围保存；拒绝不等于系统失败 |
| 不回应／暂停 | 不点击、暂缓或返回探索 | 不把沉默当确认，不持续催促；保持已保存成果和仍待处理的问题 |
| 回顾与恢复 | 查看决定依据、旧版、整份或城市级恢复预览 | 只读查看不生效；恢复通过新版本与当前约束/事实校验；不擦除后续历史 |
| 提交异常 | 超时、重复点击、恢复失败、其他设备已更新 | 保留已保存成果；提交结果未知先核实权威状态；同一意图不得重复生效；旧授权/提案/事实不跨会话复活 |

**事实状态。** 必须区分未核验、概略估算、指定条件核验、已知冲突、过期需重查、工具失败与可信确认无服务。高影响日期依赖应在用户投入大量后续规划前提示；日期未知不普遍阻断探索和当前层次的骨架决定。冲突提示须定位并持续可见，不以一次关闭消失。保存范围包括当前版本、决定、依据、未知与变更记录。[KB-06](sources/KB-06.md) §6.7–6.12；PRD-007/008。

## 跨 Flow 连续性与恢复

1. **查看焦点 ≠ 修改目标。** 地图显示阿斯旺时，AI 仍可正确回答先前卢克索任务；新输入指代不明且影响重要操作时才澄清。页面切换不结束编辑会话。[KB-07](sources/KB-07.md) §7.3。
2. **兴趣／候选／假设／草稿／历史查看 ≠ 有效采用。** 只有合法业务操作能改变已采用方案；所有入口读同一权威旅行。[KB-07](sources/KB-07.md) §7.1、§7.3。
3. **跨会话恢复最后成功保存点。** 恢复任务、比较对象及当时版本、草稿、语义视图和暂缓状态，再从当前旅行重建依据；旧输入只读、旧授权和旧可执行资格不复活。旧事实重新检查时效。[KB-07](sources/KB-07.md) §7.2；[DC 恢复合同](../../decision-context-v0.1/04_工程规格/05_持久检查点与跨会话恢复规格.md)。
4. **失败按范围处理。** AI/工具失败不销毁已保存草稿或有效版；部分分析成功只保留仍适用部分；超时提交判“结果未知”并查权威状态；并发基础版本不符不静默覆盖。[KB-07](sources/KB-07.md) §7.4。
5. **回答交付 ≠ 行动成功 ≠ 用户决定。** 推荐可跳过，实际回应要交付，用户价值选择仍属用户；不能因入口出现、工具成功或用户未回应关闭任务。[KB-08](sources/KB-08.md) HX-22；[NAP](../../Next-Action-Policy-V0.1/policy/behavior-spec.md) R03。
