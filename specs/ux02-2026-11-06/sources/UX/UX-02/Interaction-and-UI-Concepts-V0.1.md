## 1. 横向 Human × AI 规则

下列 HX 编号沿用 [KB-08](sources/KB-08.md) §8.2–8.5。它们横跨多个 Flow；详细适用条件及反例保存在该源资料。本归档以 [核心流程](Core-UX-Flow-V0.1.md) 的步骤和 [工程矩阵](Engineering-Impact-Matrix-V0.1.md) 的守卫为执行入口。

| ID | 已形成的行为边界 | 主要承接 |
|---|---|---|
| HX-01 | 当前明确目标优先于系统普通阶段推进；有必要的安全和授权阻断仍须处理 | F1/F2/F3、NAP |
| HX-02 | 理解目标要结合任务、对象、条件和前文；一句话可能包含多任务 | F1–F6、语义/DC |
| HX-03 | 存在缺口不自动等于现在打扰用户；比较行动价值与成本 | F2、NAP |
| HX-04 | 可靠的后台准备与推送/提问分开 | F2/F3、NAP/运行 |
| HX-05 | 主答复之外的额外建议按条件出现；双层呈现是候选 UX，非固定控件 | F2、UX-03/04 |
| HX-06 | 跳过、拒绝、暂停、改道及合法重新讨论各按对象与范围解释 | F1/F2/F6 |
| HX-07 | 浏览、兴趣、候选、假设、草稿和确认保持分离 | 全 Flow、TS |
| HX-08 | 比较整趟旅行的获得、保留、失去、时间、交通、费用及未知 | F3/F5 |
| HX-09 | 明确采用可表达确认；新未展示的重要牺牲仍须具体裁决 | F3/F4/F6 |
| HX-10 | 浏览模式与编辑会话分离，焦点切换不自动提交 | F1/F4 |
| HX-11 | 地图、时间轴和明确对话指令编辑同一草稿 | F4、前端/DC |
| HX-12 | 假设预览独立于草稿和有效版，只有明确采用才进入写入链 | F5、TS/DC |
| HX-13 | 纠错绑定对象、操作、条件和版本；不把修正当第二次增量操作 | F1/F5 |
| HX-14 | 不同规划内容的确认范围不同；不得由城市骨架确认推导具体预订 | F3/F6 |
| HX-15 | 规划决定与事实核验分轴，用户同意不提高外部证据层级 | F3/F6 |

| HX-18 | 重要历史可回看；恢复需新版本和当前条件校验 | F3/F5/F6 |
| HX-19 | 跨 Flow 共享权威旅行，任务、草稿、焦点有各自边界 | UX-02.5-B |
| HX-20 | 恢复工作进度和当前依据，不只是聊天文字 | UX-02.5-A |
| HX-21 | 系统/网络失败先保护已保存成果，提交未知查权威结果 | UX-02.5-C |
| HX-22 | 答复已交付、行动已成功、用户已确认是不同结果 | F2/F6、NAP |
| HX-23 | 行动价值须用运行和用户效果验证，不能只凭 AI 自评 | F2、Evals |

**优先级和权限。** 正式 NAP 已规定用户直接请求、必要授权、可靠主动准备、拒绝后有限机会成本提示及改道处理；它是工程规格评审候选，不能把本表解释为 NAP 已在产品中运行。[NAP 行为规范](../../Next-Action-Policy-V0.1/policy/behavior-spec.md) P01–P05/R01–R06；[KB-08](sources/KB-08.md) §8.2–8.5。

## 2. 工作空间与状态层

底稿记载的后期方向：**顶部横向时间轴 + 左/中央主地图 + 右侧较窄上下文信息区 + 地图内城市浮层 + 可用的 AI 对话入口**。地图主要承担空间关系与直接操作；时间轴承担顺序、停留和变化；右侧可在整趟旅行摘要与城市聚焦摘要间切换。对话与视觉区域同读一份旅行，但地图焦点、对话任务焦点、编辑目标允许不同。[KB-04](sources/KB-04.md) §4.3–4.4；[KB-08](sources/KB-08.md) §8.6。

以下是**根据底稿重排**的信息结构，不是原始截图或最终页面：

```text
顶部：旅行时间轴（城市顺序、停留、相关变化）
主体：大面积地图（城市/连接/体验/城市浮层） | 右侧上下文区（整趟或城市摘要）
任务层：AI 对话、推荐、比较、澄清、编辑与恢复入口
状态层：有效版 / 草稿 / 假设；已知 / 估算 / 待核验 / 已知冲突 / 过期 / 失败
```

不同状态必须让用户辨认：浏览与编辑、已保存与未确认保存、草稿冲突与有效版冲突、已采用与已核验、只读历史与恢复预览、提交中与提交结果未知。视觉编码、面板尺寸、对话固定方式、移动端组织和比较视图形式尚待 UX-04 验证。[KB-07](sources/KB-07.md) §7.4.12；[KB-08](sources/KB-08.md) §8.14–8.15。

## 4. 方案演化与废弃方向

以下 D-01～07 是底稿明确记录的替换关系。D-01～03 可追溯正式 P01 材料；D-04～07 仅有历史摘要支持，尚缺原始对话核验。[KB-09](sources/KB-09.md) §9.8–9.10。

| 编号 | 初期方向 | 后续调整 | 调整原因 | 依据等级 |
|---|---|---|---|---|
| D-01 | 只按决策缺口选择下一步             | 缺口作为输入，进一步比较行动价值与成本 | 不能充分比较多个合理动作   | P01 正式资料 C   |
| D-02 | 每轮强制提供额外下一步建议           | 建议有条件出现，允许不介入       | 重复打扰、增加注意力成本   | P01 正式资料 C   |
| D-03 | 草案优先作为所有任务的默认策略         | 按当前目标选择合适动作         | 锚定与返工风险        | P01 正式资料 C   |
| D-04 | 为 What-if 建立独立默认页面或模式   | 复用已有工作空间并隔离假设       | 减少重复体系与切换成本    | F5 历史摘要 B    |
| D-05 | 将规划深度 L1/L2/L3 变成固定确认关卡 | 按条件依赖进行渐进式确认        | 用户行为非线性，同层依赖不同 | F6 历史摘要 B    |
| D-06 | 编辑中每项改变都立即全面重算          | 即时确定性反馈，适时聚合分析      | 中断连续操作、增加成本    | F4 历史摘要 B    |
| D-07 | 对已经明确选择的方案再进行普通重复确认     | 选择即确认，保留必要校验        | 冗余交互且无新增授权价值   | F3/F4 历史摘要 B |

## 5. UX-04 必须验证的界面问题

- 探索首屏地图、城市、图片与体验卡的注意力分配；左右滑动是否比点击更清楚，兴趣反馈如何明确区分采用。
- 时间轴、地图、右侧上下文与 AI 对话在不同屏宽下的布局及同步；浏览、编辑、假设、历史只读的可辨认性。
- 比较视图如何同时呈现全程取舍、事实等级、未完成校验与新增重要牺牲。
- 自动保存、提交中、提交结果未知、部分计算、并发冲突和恢复失败的可理解反馈；所有状态需与权威业务结果一致。
- 版本历史、整份及城市级恢复的预览、影响范围与确认路径；两种恢复已由 Owner 于 2026-11-05 裁决纳入 MVP，具体界面形式仍待 UX-04 验证。
