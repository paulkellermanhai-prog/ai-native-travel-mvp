# UX-02 E01–E32｜逐项责任、观察断言与依赖

来源：`../../UX/UX-02/Engineering-Impact-Matrix-V0.1.md`；原编号是 UX 编号，不能混同工程 E03/E04 阶段。以下断言为验收要求，均不等于已完成。原设计中的候选界面继续按 UX-04 验证，NAP 不负责生成 UI、TS 真值或 DC 任务。

| ID／用户行为 | 主要承接模块 | NAP 责任 | 必须观察的断言 | 未覆盖／依赖 |
|---|---|---|---|---|
| E01 不提供日期/预算也开始探索 → 展示有限城市、体验和地图 | 前端内容组织、数据内容集、DC 探索任务 | P05 探索不强问 | 空日期、空预算可浏览、提问，不被强制追问 | 前端、内容与地图；真实数据待验 |
| E02 点城市、地图连接或体验卡 → 聚焦信息，不改变旅行骨架 | 前端焦点与 UI State、DC 语义视图、TS 变更边界 | G01 焦点不等写入 | 切换焦点后 TS 决定/骨架不变 | UI 焦点、DC task/target 与 TS 零写待验 |
| E03 喜欢/不喜欢体验 → 记录情境化兴趣，不自动采用 | TS 偏好/候选/决定区分、语义理解、前端反馈 | G01/P05 区分兴趣与采用 | 连续反馈及撤回不生成已采用行程 | 真实反馈事件、TS 状态与 UX 待验 |
| E04 查看交通连接 → 标出依据、条件、未知，不把示意线当班次 | 数据来源与时间戳、事实等级、地图卡、计算 | R02/G02 限制事实层级 | 缺班次与工具失败均不显示确定可达 | 真实交通来源、日期和 UI 待验 |
| E05 用户继续探索或发问 → AI 在当前焦点回答，必要时提出下一步 | DC 当前任务/焦点、NAP 行动选择、语义输入 | G01/G03 回应当前焦点 | 同一句话在不同焦点下不误操作；无价值时不强推 | E03 语义、任务与真实语言待验 |
| E06 出现重大缺口或冲突 → AI 选择澄清、准备、比较或等待 | DC gap、NAP 候选/价值/成本、编排任务 | G02/G03/G04 资格、价值与时机 | 既不过度打断，也不漏掉会改变判断的缺口 | 语义解释、E04 策略和用户效果待验 |
| E07 用户跳过推荐或改道 → 停止当前推动，保留已有成果 | NAP 暂停/拒绝、DC 任务切换、前端入口 | R01/R03/G05 按范围跳过和改道 | 跳过后可进入地图/比较；旧建议不反复出现 | 跨入口事件、DC 任务及展示记录待验 |
| E08 请求方案 → 仅生成有实质取舍的候选并解释 | TS Candidate/Skeleton、NAP 行动、路线/成本计算 | G03/R06 实质差异及不足降级 | 两案不只是文案差异；无意义时不凑数 | 候选引擎与路线/成本计算待验 |
| E09 比较骨架 → 呈现全程增益、保留、损失、未知及事实证据 | 比较读模型、TS 版本/评估、数据计算、前端比较 | G03/R06 比较有来源的得失未知 | 取舍可解释，未知不被排成确定性评分 | TS 评估、比较读面、来源与 UI 待验 |
| E10 明确选择已展示的重要取舍 → 采用候选；新牺牲另作必要判断 | TS OperationIntent/ChangeRecord、NAP 授权门槛、后端提交 | P02/CT-04 同范围合法选择与新牺牲 | 单次明确选择可提交；隐藏牺牲不得静默采用 | 受信展示/Grant、TS 写桥与 UI 待验 |
| E11 查看历史 → 只读旧版、差异、决定理由 | TS 版本/ChangeRecord、历史读取接口、UI | G01/G02 历史只读且旧事实不作当前证据 | 查看旧版不改有效版；事实过期有提示 | 授权历史读取、事实效期与 UI 待验 |
| E12 整份恢复旧版 → 新建版本并核验当前约束 | TS 版本分叉/意图、事实重查、后端并发保护 | G02/G05 预览整份恢复与当前授权 | 恢复失败保留当前有效版；不能直接覆盖历史 | PR #13 固定 head 限定工程范围已验收；合并及跨模块联合事务待验 |
| E13 恢复某城市 → 预览受影响交通、停留和成本后新建版本 | 对象级差异、依赖重算、TS 版本/后端事务、UI | G02/G05 单城预览与连锁影响 | 只恢复目标城市及必要连锁变化；失败无半成品 | PR #13 固定 head 单分支专项已验收；集成后连锁计算、无关城市及跨模块事务待验 |
| E14 从地图、时间轴或对话编辑 → 操作同一草稿 | 前端统一 Draft ID、DC 焦点、TS 变更事件、后端同步 | R05/G01 不将焦点变编辑目标 | 三入口看到相同草稿，不互相覆盖 | 三入口 UI、DC 目标和统一 Draft ID 待验 |
| E15 连续改动 → 即时显示确定的结构影响，聚合重算复杂判断 | 运行编排、局部计算、异步状态、前端反馈 | R05/G05 消费即时结构与版本绑定的异步结果 | 旧版异步结果不覆盖新草稿；编辑不中断 | 前端即时结构反馈、异步关联对象及版本待验 |
| E16 完成一组编辑 → 展示重要变化、确认范围，再安全提交 | TS 意图/变更、NAP 确认、后端 CAS/幂等 | P02/R05 重要变化按范围授权 | 未授权不改有效版；无需每一笔普通重复确认 | TS 守卫、可信事件和界面待验 |
| E17 说“如果…/改成…” → 区分有效 A、草稿 B、假设 C | 语义意图、TS Scenario/Plan 分离、DC 焦点、UI 状态 | R04/R05 假设不采用，基线区分 A/B | 纯假设不产生正式变更；基线明确 | 语义解释、A/B 基线引用、TS/DC 与 UI 待验 |
| E18 修正自己的指令 → 以新意图替换受影响待处理计算 | 事件关联、取消/作废异步任务、版本校验 | G01/G05 纠错关联并淘汰旧工作 | “不是三天，是两天”不重复叠加时长 | 异步取消/版本关联及语义解释待验 |
| E19 看假设结果再采用 → 明确授权后转为变更，保护已确认体验 | TS 候选→意图/决定、NAP 权限、依赖重算 | P02/R04 采用须当前授权 | 只看假设不生效；采用后产生可追踪版本 | TS 方案守卫、用户授权及 UI 待验 |
| E20 无日期确认概念骨架 → 保存决定范围，同时标记待核验现实条件 | TS 确认范围/事实状态、UI 提示、NAP 权限 | R02/P02 概念选择与现实核验分离 | 无日期可确认概念方向，不能显示具体班次已可行 | TS 确认范围、数据服务及 UI 待验 |
| E21 后补日期或条件 → 定位受影响安排并重新核验 | TS 依赖/版本、事实 TTL、计算与数据工具 | R02/G05 相关条件变化重新核验 | 新日期只使相关证据过期；冲突准确定位 | 事实服务、影响传播及结果关联待验 |
| E22 看到已知冲突、未知或工具失败 → 不混淆，持续标注到相关对象 | 事实/错误分类、前端多视图同步、后端持久化 | R02/CT-03 结果失败、未知与冲突分离 | 查询失败不被当作无车；已知冲突不消失 | 前端持续对象关联和事实状态字典待验 |
| E23 跨会话返回 → 读取最后成功检查点，恢复任务/焦点/草稿引用，再核当前事实 | DC checkpoint/恢复、TS 重读、前端入口 | RT-05 仅恢复已 ACK 现场并重鉴权 | 恢复不复活旧授权、不覆盖当前 TS；失效项可解释 | E03-05/06 生产 checkpoint、身份与 E11 待验 |
| E24 跨 Flow 切换 → 保留工作成果，区分浏览焦点与编辑目标 | DC 任务/焦点、TS 草稿/版本、前端导航 | G01/R03 保持任务、焦点、草稿独立 | 返回编辑时接同一草稿，浏览旧版不误编辑 | 导航及三入口同草稿与历史焦点待验 |
| E25 编辑时断线或 AI 失败 → 保留已成功保存的成果，说明未保存/部分结果 | DC checkpoint ACK、TS 保存状态、前端错误 | RT-05 保存 ACK 与业务效果独立 | 不把未 ACK 内容说成已保存；恢复可继续 | 前端保存状态与 DC checkpoint ACK 待验 |
| E26 工具超时/部分计算 → 区分未知与失败、保留可用分析 | 编排分项状态、数据工具、前端部分结果 | RT-03 区分部分、失败、未知并重评 | 失败子项不污染成功子项；不捏造价格/班次 | 真实工具、子任务汇总与部分结果 UI 待验 |
| E27 提交超时或重复点击 → 查询权威状态，幂等处理 | TS/DC/NAP 提交协议、后端 idempotency/CAS、UI | RT-05 未知业务先查权威回执 | 结果未知期间不显示成功/失败；重试不双写 | 跨模块操作 ID、业务权威回执、幂等和 UI 待验 |
| E28 别处更新有效版、旧草稿仍在 → 保留草稿并处理并发冲突 | TS 版本前提、DC CAS、后端合并/重建路径 | G02/G05 版本冲突重读，保留草稿 | 旧草稿不能覆盖新有效版，用户成果可找回 | TS CAS、DC 保存与 UI 冲突修复待验 |
| E29 AI 给建议、用户拒绝/暂停/改道 → 有条件行动且权限不越界 | NAP 价值/成本/Grant、DC 当前焦点、Evals | G02/G04/G05 授权、拒绝及干预时机 | 无授权不更改决定；拒绝后不会循环推动 | 真实拒绝范围、事件记录及 UX/Evals 待验 |
| E30 展示 108 项初步 UI 状态 → 同步有效/草稿/假设/历史及错误 | 前端状态机、设计系统、后端读模型 | G01/R04/R05 消费多视图状态，不定义布局 | 同一业务对象在地图、时间轴、对话无状态矛盾 | 地图/时间轴/对话 UI 状态与设计验证待验 |
| E31 完成正常、异常、越权、恢复与成本校验 → 留可追溯运行证据 | Evals 数据集、回放、日志、真实数据和用户研究 | CT-05/质量评测 保留可追溯结果 | 同一场景同时断言业务状态、UI 文案、权限与事实证据 | 真实模型、工具、UI、HTTP/PG 和用户研究待验 |
| E32 要求国际机票实时优化、酒店深选、预订支付、逐日细排或旅途中事故处理 | 额外数据、交易和履约系统 | P02/MVP 非目标，不扩展交易承诺 | MVP 测试不以超范围能力判失败 | 产品范围与未来能力另行决策 |

E15 补充：可确定的结构变化及时反馈；复杂事实及全程影响异步汇总，结果绑定对象、草稿及版本。E17 补充：C 必须明确基于有效 A 或草稿 B，查看不覆盖 A/B。E30 补充：同一业务对象的有效、草稿、假设、历史和错误状态在地图、时间轴与对话一致；108 项初步界面由 UX-04 验证。

真实 Evals 须记录当前 TS/DC 版本、授权与受信事件、各入口 UI 状态、实际回执和副作用；当前逐项矩阵只定义验收，不报告产品或运行通过。
