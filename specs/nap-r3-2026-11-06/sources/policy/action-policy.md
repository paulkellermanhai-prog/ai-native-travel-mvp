# NAP｜通用行动决策机制

本文是G01～G05、行动分类与竞争裁决的唯一规范定义位置。产品原则见[行为规范](behavior-spec.md)，运行约束引用[RT](../engineering/runtime.md)，接口见[CT](../engineering/contracts.md)。

<a id="g01"></a>
## G01｜当前意图、需求与决策上下文理解

用户输入、直接操作、工具反馈、有效状态变化或重新相关的历史需求触发理解。消费当前Trip State、同版有效DC读取包、最新事件及有来源的运行记录，识别当前明确请求、有效未解决请求、决策缺口、探索/比较/假设/确认/拒绝/纠错/停止语义、对象范围及条件。

输出当前需求和缺口的解释，不产生新业务真值或授权。模糊偏好不精确化，浏览不证明充分认知，新一句话不自动覆盖重要决定。首次任务定位由DC解释器前置协议承担，NAP不要求先有Action才能组装Context，避免循环依赖。执行连接：[RT-01](../engineering/runtime.md#rt-01)；评测S02/S03/F04/M05/N02。

<a id="g03"></a>
## G03｜候选生成与决策价值选择

分两个逻辑环节：先由当前请求/缺口提出候选方向；G02校验后，再与G04共同选合格行动。依据当前意图、认知/价值/现实缺口、可用候选、增量价值和交互成本。优先真正阻断、直接满足请求、重要缺口、可改变取舍的信息、有意义比较及更低成本的等效帮助。

不使用全局固定Action顺序、未经验证的加权总分或“信息越多越好”；不把每轮骨架推进最大化。高价值不能使不合格行为获得资格。执行连接：[RT-01](../engineering/runtime.md#rt-01)、[RT-02](../engineering/runtime.md#rt-02)；评测C01～C07、S04/X06。

<a id="g02"></a>
## G02｜资格、权限与可信边界

候选存在后、关键执行前、依赖变化后、工具结果采用前及旧入口点击时检查：权限、活动hard、必要输入、工具能力、来源/时效/核验级别、适用条件和MVP范围。结果区分合格、强制禁止、缺条件、证据不足、当前失效和超出能力；后五类不能直接执行原行为。

不合格的是行动路径，不是用户需求。优先寻找合法替代、概略降级、最小澄清或解释阻碍；不能由价值判断豁免。主观体验值不由G02替用户判断。确定性与模型判断边界见[RT-06](../engineering/runtime.md#rt-06)；评测F06/F08/X02/X03/N03/N10。

<a id="g04"></a>
## G04｜自主准备与用户注意力分配

与G03共同判断是否自主做可靠准备、需要用户参与的当前主Action、其他合格次级Action、或不新增主动行动。四去向可组合：后台核验后完成主要回应并给少量可选入口，不必拆成互斥状态。

同时考虑价值、时机、权限、最近拒绝/改道、必要性和交互负担。次级不必全执行；不为丰富界面制造推荐；不新增推荐仍要合理处理明确请求。最终视觉布局不由此确定。[RT-04](../engineering/runtime.md#rt-04)负责呈现回执与改道；评测X09/X10/C07/N06/N07。

<a id="g05"></a>
## G05｜结果、状态连续与动态重评估

处理完成、部分完成、失败、暂缓、跳过、拒绝、撤回、失效、恢复及条件变化。以真实结果及最新State/DC判断范围，保留有效请求、拒绝依据和用户决定；条件变化使依赖重查，不直接撤销价值决定。一次查询成功不等于整个请求完成。

新当前意图、工具失败/迟到、旧入口、证据过期和主动重开都可触发重评估；不自动重放旧动作、不重复推送已拒绝或无新增价值内容、不另立状态真相。工程责任：[RT-03](../engineering/runtime.md#rt-03)、[RT-04](../engineering/runtime.md#rt-04)、[RT-05](../engineering/runtime.md#rt-05)；评测M01～M06/N08。

<a id="action-goals"></a>
## 五类决策目标与横向能力

| 目标ID | 正式含义 | 示例 |
|---|---|---|
| D1 | 认知探索、差异化信息理解 | 空间/体验参照、概略季节 |
| D2 | 现实事实核验 | 适用日期的交通或体验条件 |
| D3 | 计算、比较与取舍分析 | 两骨架收益/代价/未知 |
| D4 | 最小必要澄清 | 真正缺少的日期/授权范围 |
| D5 | 请求关键决定与确认 | 当前具体版本的重要采用 |

状态处理、结果交付、暂缓恢复、执行反馈、重新校验、追踪是横向能力，可服务多个目标。一次比较可内部检索、核验、计算、交付，不需要四个可见Action。D编号在本工程包中作为本包契约目标码固定，未修改TS/DC任何枚举；旧七类标签仅保留在[历史决策](../DECISIONS.md#dec-03)。

<a id="competition"></a>
## 竞争裁决：资格先于价值，时机与价值共同决定

1. 强制边界：排除越权、hard破坏、无必要授权、虚假事实、违背有效停止边界及超范围承诺。
2. 真正阻断与当前明确请求：只有真实阻断A的B才能前置；其他缺口不能无限抢占。
3. 增量价值：补当前判断最关键的缺口；有充分比较依据时可比较，用户继续探索则接纳。
4. 成本与自主性：能可靠低风险自主准备则积极承担，需注意力时控制提问/打断；必要确认不可省。
5. 主次与连续性：当前主行为清楚，次级可选，工作空间入口持续可用，执行/点击前重新校验。

这是分层裁决，不是数字求和或固定D1→D5流程。等效合理行为允许并存。模型只需给可检查的简短理由与引用，不要求提交隐藏推理过程。

<a id="continuity"></a>
## 澄清、拒绝、撤回与恢复的应用方式

明确班次问题缺日期则最小澄清，概略季节无需精确日期。拒绝某Action不等于拒绝城市；停止介绍不等于取消住宿；未点击不等于撤回；部分交付不等于完成。条件性放弃保留适用条件，条件未知不判true。主动重开恢复讨论，不自动恢复旧业务状态/授权；真正Candidate重入仍依[CT-04](../engineering/contracts.md#ct-04)。

历史需求重入竞争按[R03](behavior-spec.md#nap-r03)。交付、撤回、提示历史用[CT-05](../engineering/contracts.md#ct-05)的运行事实记录承载；不覆盖Constraint/Decision，不把DC open标签当催办命令。

<a id="business-example"></a>
## 完整实例：“阿斯旺值得加吗？我担心转场”

输入：普通候选，用户有文化兴趣；日期/起止节点已知，低风险可信交通工具可用，未停止讨论，尚无阿斯旺确认决定。

| 事件/责任 | 行为 | 可观察结果 |
|---|---|---|
| G01 | 识别取舍问题与代价缺口，读取当前约束和历史偏好 | 不把顾虑变硬小时上限 |
| G03候选 | D1补体验、D2核验交通、D3加入/不加入比较、D4继续问条件 | 候选是建议，不是已获执行权 |
| G02 | 日期/来源/权限足够，D2可做；无必要条件缺失不泛化追问 | 低风险查询合格，直接采用不合格 |
| G03/G04 | 交通准备＋价值比较为主，体验补充按缺口整合；不催最终选择 | 无多余查询批准，用户注意力用于得失 |
| 执行前复核 | 条件仍当前才查；若用户改日期，旧结果仅历史 | 结果绑定原输入与期限 |
| G05 | 工具超时则保留未知并降级说明；成功则仅按证据层级交付 | 记录实质交付，尚未作城市决定 |
| 后续用户 | “不去了”按R01处理；“确认加这版”按P02/TS守卫 | 不因查询成功自动加入或确认事实 |

该表是协作实例，不规定五个独立服务或必须串行调用。可先并行准备独立事实，涉及同一业务提交仍按原原子守卫。


## 八项机制与恢复场景的裁决补充

G01 区分当前事件与授权读取的历史证据，缺证保持未知；G03/G04 在资格之后比较真实不同的帮助、可由系统承担的准备、延后及不介入，动态考虑任务累计负担和下一合理时机，不设固定阈值。G02 按当前事实范围、时效、来源和 TS 争议清单校验，不将争议单条事实用于精确采用。G05 对历史恢复、授权或版本变化重新组装依据，保留用户选择，不从工具成功、展示、沉默或保存回执推断采用或效果。逐项参见 [AC8/UX-02](../engineering/ac8-ux02-integration.md)。
