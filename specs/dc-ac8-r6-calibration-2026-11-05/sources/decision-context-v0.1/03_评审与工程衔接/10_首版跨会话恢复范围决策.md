# 首版跨会话恢复｜Product Owner 范围决策

日期：2026-10-24。来源 U05：用户明确“首版我需要做到精确恢复跨会话暂停现场”。U06 要求完成工程收口。状态：**产品范围已确认，工程规格/参考实现/本地故障验收已完成，待最终人工审核**。O1 不再未决；本页覆盖旧 R0 建议及“首版不包含精确恢复”的范围假设。当前完成度见 [恢复工程报告](11_跨会话恢复工程收口报告.md)。

## 1. 首版 P0 必须恢复什么

| 内容 | 恢复要求 |
|---|---|
| 判断问题和关联 | 当前主问题、相关子问题、继续/暂停/当次已处理状态及来源；E/Q/S 不因关闭会话丢失 |
| 比较工作现场 | 正在比较哪些候选/骨架版本、主要焦点与查看的差异；不能只留下旅行数据后要求用户重讲 |
| 暂缓事项 | 哪些问题用户已暂时搁置，保留限制与暂缓意图，不因重进会话重新催办 |
| 未提交草稿 | 当前暂定/假设编辑、待处理要求和原话/修改意图可找回；明确未提交/未确认/失败，不升级为有效业务状态 |
| 页面语义现场 | 入口/视图、比较对象、选中对象、展开的相关讨论等足以继续工作的语义焦点；不把像素级滚动位置和动画帧还原作为本次核心验收门槛 |

“精确”以最后一个**成功保存并可确认的运行检查点**为基准；尚未收到保存确认的本地输入不能假报已可靠保存。保存中/失败要可感知，不靠用户每一步手动保存或确认来弥补。自动保存触发、冲突协议和容量已收口于 [恢复工程规格](../04_工程规格/05_持久检查点与跨会话恢复规格.md)；真实客户端定时与页面接入须单独验收。

## 2. 恢复现场不恢复什么

- 不恢复过期事实的现实有效性：重新检查当前约束、时刻、适用性，重建 Context/Hydration。
- 不恢复旧确认提案/Grant 的授权效力：沿用原摘要、版本、范围、期限规则，禁止自动重放提交。
- 不恢复已撤回的采用：历史 A/B 可找回，根引用仍以当前权威状态为准。
- 不把草稿、假设或失败变更并入有效状态；草稿基准版本落后时展示差异/冲突，不静默应用。

## 3. 对既有架构的影响

新增的是**持久运行检查点（Persistent Runtime Checkpoint）能力**，不是第二份 Trip State，也不是新增第十一业务对象。检查点可保存任务/焦点等运行元信息，以及严格标识为未提交的草稿；已生效业务内容以权威 ID/版本引用为主，不能在恢复缓存里另维护有效预算、偏好或采用真值。

仅有 task_key 书签不足以覆盖本次范围，因为草稿和语义视图也需要恢复。另一方面，这不要求建设完整任务事件溯源/工作流平台。本次采用 SQLite 本地事务参考后端、检查点 CAS 与保存回执；不是生产数据库选型承诺，不修改已确认机制 B、状态传播和 AI 写入边界。

## 4. 必须新增的验收

| ID | 场景 | 必须观察到 |
|---|---|---|
| DC-R01 | 同用户关闭会话，在新进程/新会话回来 | 无需重讲即可定位同一问题、比较对象和语义焦点，不依赖原 Runtime 内存 |
| DC-R02 | 中断期间业务状态改变/事实到期 | 找回工作现场，但依据按当前状态重建，陈旧内容明确标识 |
| DC-R03 | 带未提交/假设草稿离开 | 草稿与原意可找回；根/有效约束不被草稿覆盖 |
| DC-R04 | 撤回采用后离开再回来 | 讨论关系恢复，旧采用与旧授权不复活 |
| DC-R05 | 两会话并发编辑、账号切换 | 检查点版本冲突可检测，不静默覆盖；未授权用户无法读到他人草稿/旅行 |
| DC-R06 | 保存时断网/进程崩溃 | 恢复最后一次可证保存点；不把未保存内容假报已保存，不重放重要写入 |
| DC-R07 | 暂缓问题后跨会话恢复 | 保留暂缓意图；无新相关变化不因会话重开自动催办；决定性限制仍明确 |

DC-R01–07 已转成实际测试，包含独立进程、跨进程 CAS、提交前后强制终止、丢回执重试和旧授权隔离；结果见 [实际验证报告](../90_可运行工程包/VALIDATION_REPORT.md)。不是借用原 174 项结果冒充新增证据，也不声称真实网络/前端已测。
