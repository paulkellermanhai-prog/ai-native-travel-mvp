# E11｜宿主交互证据数据契约与跨轮验收轨迹

日期：2026-11-05。状态：`host-interaction-evidence/v1` **工程候选合同**，供 E03-00 Gate A 校准与获批后的 E03-01 底座设计；未在 GitHub 宿主实现。技术裁决及宿主现状见[DC-AC8-PROTOCOL-01](15_DC-AC8协议裁决与宿主证据接口交接.md)。本合同属于宿主内部设施，独立于 DC 0.1.0 的 20 份 Schema、Packet、Checkpoint 格式 1 和 TS 业务状态。

## 1. 先记录事件，再关联任务

用户输入抵达时尚未知道 `task_key`。唯一合法顺序是：**鉴权与旅行成员核验 → 持久保存原始用户事件并获得服务器生成的 `event_id`/回执 → 解释器提出任务 → DC `open_turn` 验证并保存当前任务现场 → 宿主建立 `event_id → task_key` 关联**。事件写入不等待模型给任务名；任务解释失败时事件保持未关联，不能改写为“已确认用户意图”。DC `open-turn.event` 使用同一服务器事件 ID、原文、入口、服务器接收时间和受信来源引用，例如 `host-interaction:<event_id>`；宿主适配器须验证这五项与已保存记录逐项相同。现有 Python Runtime 仅检查结构/区段，不做这项宿主绑定；生产适配不可直接信任请求 JSON。

### 受信事件记录与写入回执

| 属性 | v1 约束 |
|---|---|
| 身份和范围 | 当前经验证 Cookie Session 得到用户 ID；在写事务前及事务内核对 TripMembership。`owner_id/trip_id/workspace_key/session_ref` 由宿主绑定，不能来自模型/客户端自报 actor 或 owner。共享旅行成员不共享未提交原话。 |
| 事件 | `event_id` 由服务器产生，符合现行 DC event ID 字符规则；记录 `entry`、完整原话 `text`、服务器 `received_at` 与数据库 `recorded_at`、稳定单调序号、来源通道 `authenticated_user`。客户端时间仅可作未核验元数据，不代替服务器时间。Model/System/Tool 事件须另分类，不能写成用户原话。 |
| 幂等 | 客户端为一次提交提供 `idempotency_key`；键在 owner/trip/workspace 范围内唯一并绑定原始输入摘要。相同键与摘要重试返回同一 event_id/回执；同键异内容冲突，不能悄悄生成第二条。服务器事件 ID 与客户端键不同。 |
| 持久边界 | 事件正文、作用域、摘要、序号和幂等回执在一个数据库事务中提交。仅在持久提交后回 `durable=true`；提交前失败无成功回执，提交后回执丢失以原键重查，不猜测是否保存。服务器重启后同键可读到相同事件。 |
| 长度与权限 | 正文需满足 DC 当轮 event 上限 16,000 Unicode 字符；无生产保留期限批准前仅隔离测试数据可写。正文不写应用日志、TS history、Checkpoint 或未经授权的分析表。 |

`event_id` 不能由模型任意挑选；旧 `event_id` 不能重新登记成新的当前用户指令。记录成功只证明用户原话被受信接收，不证明解释器理解正确、任务关联正确或业务写入获准。

## 2. Task 关联与修订历史

宿主单独维护**事件记录**与**关联日志**；不修改原始事件内容。注册器只在 DC 对当前 `open_turn` 成功校验、Task 归属/分支/关系可核且事件与本次 Turn 绑定后，才向关联服务提交受信 `event_id`、一个或多个 `task_key`、当前 owner/trip/workspace、`turn_id`、预期关联修订和操作幂等键。一个事件可关联多个经验证的独立 Task；同一个 Task 可关联多轮事件。关联不是 TS 业务真值，也不能授权撤回/采用。

关联使用 append-only 的 `link_id/event_id/task_key/action/association_revision/linked_at/source_turn_id` 记录。`action` 是 link、unlink 或 supersede；纠错/改道新增关联修订，不覆盖旧证据。读取时只使用当前有效、已验证的关联，同时允许有权限的审计追溯旧关联及变更原因。相同关联键/内容重试只产生一份修订；预期修订不符返回冲突并重读，不做最后写入者覆盖。事件、Task 或主体/旅行/工作区任一不符时原子拒绝整批关联；不得部分接受多任务关联。

DC Checkpoint 与宿主记录可能位于不同存储事务，不能假装单笔跨库提交。若 event 已保存而 Task 注册失败，事件保持未关联；若 Task/Checkpoint 已确认但关联写失败，现场仍可按原合同恢复，但旧证据查询明确标为 `association_pending/unavailable`，宿主用同一事件/关联键安全重试。读取器只返回已提交的有效关联；不能因部分故障使用模型补的 task_key。删除/到期后原文不可再返回，必要墓碑仅保留最小标识和审计结果，不继续把已删除正文交给解释器。

## 3. `HostInteractionEvidenceReader` v1

内部调用输入由宿主构造：当前受信 principal、trip、workspace、已注册 Task 身份、时间窗或绑定范围的游标及页大小。读取时**重新**验证 Session、TripMembership、Task 所有权和每条事件的 owner/trip/workspace；不能复用记录时的旧成员资格。服务身份如需代理调用，仍须证明实际用户和授权范围，不得以 Model Actor 读他人未提交原话。

返回：按宿主序号稳定排序的、实际存在且当前关联有效的事件页，每条含 `event_id/text/entry/received_at/recorded_at/source_reference/owner_id/trip_id/workspace_key/association_revision/task_key`，以及与本次查询范围绑定的游标、页完成状态和证据完整性状态。游标须绑定主体/旅行/工作区/任务与固定读取高水位；下一页沿同一快照读取。关联或保留状态变化使页集合不再一致时返回明确冲突/不完整，调用方重开查询，不把缺页当成“没有更多原话”。有限页大小和时间窗由接口强制执行，不提供无限全量导出。

| 情况 | 读取结果与 DC 处理 |
|---|---|
| 完整且授权 | 只将已验证、相关的旧片段交解释器对照当前输入；保留每条独立来源，不合成“用户曾说”的虚假原话。 |
| 无记录、已删除、过期 | 明确 `missing/deleted/expired`，不从 TS history 或 Checkpoint 最近 event 补造旧轮；当前 Task/未知仍可安全恢复。 |
| 未关联、关联待补或不完整页 | 明确 `unlinked/pending/partial`，不得宣称完整证据链，也不得用缺失推断用户否定或确认。 |
| 权限撤回、跨用户/旅行/任务 | 拒绝读取且不泄露记录是否存在；已恢复的旧授权也不能被该结果复活。 |
| 来源、时间、摘要、顺序不一致或存储故障 | 不返回半可信证据供重要写入使用；保留未知，诊断信息不含原文，重试仍需当前授权。 |

访问审计记录谁、何时、对哪个旅行/任务、为何读取及结果码，避免在审计中复制原话。技术性读取页上限、错误码和游标有效期由 E03-01 锁定并做正反测试。**DC-AC8-PRIVACY-01｜待 Owner 产品/隐私裁决：**正式原话保留期限、删除可见性、用户告知和删除后的关联/审计最小保留范围。未获批准前不得启用无限期生产原话存储；可以只用隔离测试数据和可清理的测试库验证工程。这不阻止只读合同/来源校准，也不把测试数据策略冒充生产政策。

宿主内部错误须与 DC/TS 错误分开：同键异内容 `EVENT_KEY_CONFLICT`，结果不明 `EVENT_ACK_UNKNOWN`，关联修订竞争 `ASSOCIATION_CONFLICT`，待补关联 `ASSOCIATION_PENDING`，范围/游标变化 `EVIDENCE_CURSOR_STALE`，无权 `EVIDENCE_ACCESS_DENIED`，记录缺失/到期/删除分别标 `EVIDENCE_MISSING/EXPIRED/DELETED`，存储不可用 `EVIDENCE_UNAVAILABLE`。这是 E03-01 待锁定的内部错误集合，不向 DC 0.1.0 Schema 注入新枚举；调用者不得把任何失败码解释为用户没有表达过该意图。

拟议工程位置：`src/server/interaction-evidence/` 放独立合同、存储和读取适配，`prisma/schema.prisma`/新迁移只加**宿主基础设施**事件与关联表，不动 TripStateDocument 的 JSON 业务合同；复用 `src/server/auth/authorization.ts` 的真实 Session、TripMembership 和事务内重验能力。E03-01 只建立类型/合同、受信范围和隔离数据库测试底座；E03-03 完成用户事件写入/关联/读取，E03-06 接 DC 恢复，E03-07 做 HTTP/新进程联测。正式模块名可按仓库风格调整，但数据拥有权和三步时序不可改。

## 4. DC 消费和三层验收

历史原始事件可追溯，指能在授权/保留范围内取回真实原话及来源；**当前解释可重建**，指解释器据这些事件和最新 TS 重新提出当前 Task，并由测试检验语义；**旧解释候选精确重放**，还要求保存当时模型候选/版本/判断过程，v1 不承诺。旧事件不能伪装成新 `explicit` 输入，不能直接触发 TS 命令；现行 `Task.evidence` 仍精确绑定当前 event 的原文区段，旧片段保留在宿主侧。解释器可用已核旧证据校准本轮 `Task.question/certainty/target_ids` 的候选，再由现有 DC 合同和最新 TS 检验对象归属；不得把旧片段塞进本轮 `Task.evidence` 伪称当前原话。纠错追加新事件与关联修订，旧原话继续可追溯，但当前 Task 可局部校准，其他任务和已确认决定不被解释改写。恢复先按 Checkpoint 最后成功点找回 Task/Focus/草稿，再读取**最新 TS**，最后可选读宿主旧证据；证据不可得不使旧 Packet/Grant 生效。

**R1｜Task/Checkpoint：**本地 Python 参考可测最后成功点、CAS、回执、歧义只读、旧授权隔离；它不实现宿主日志。**R2｜历史原话与理解证据：**E03-01 可建立独立合同/错误与隔离测试基座，E03-03/06/07 才能测真实写入、关联、分页、新进程读取及权限。**R3｜真实语义和行动连续：**解释器、NAP、UX 和 Evals 的多轮实测，不能由形状/参考测试替代。

可复用轨迹：用户依次说“阿斯旺太远了，怕折腾”“其实还是很想去的”“看看有没有舒服一点的交通方式”，暂停并保存，结束进程，重新登录后说“继续之前阿斯旺那个交通问题”。R2 应验证三个服务器事件 ID 先各自持久，再关联同一 Task 或经验证的相关 Task；原话不被覆盖，新进程按范围重读且旧授权无效。R3 才判断“顾虑→纠正→交通比较”的解释是否正确，不从 TS 无关对象推定用户取消阿斯旺。故障轨迹覆盖相同键重试/异内容冲突、事件已存而关联失败、关联 CAS 竞争、缺页/乱序、记录删除/到期、权限撤回、不同用户/旅行/任务串读及最新 TS 变化。每层分别报告通过数，不能将 R1+合成 R2 写作完整 E11。
