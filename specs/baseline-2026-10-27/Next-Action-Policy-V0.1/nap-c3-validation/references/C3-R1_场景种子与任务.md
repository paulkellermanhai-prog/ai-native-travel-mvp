它们作为产品级评测种子，不是统计学意义上的充分样本，也不保证覆盖所有真实用户行为。

## 2. 复杂多轮 Scenario Walkthrough

### W01｜认知不足、用户放弃与有限机会成本提示

**初始条件：** 用户关注历史文化，阿斯旺只是普通候选，尚未了解足以影响取舍的部分体验信息，没有明确禁止继续讨论。

| 轮次 | 事件 | G01～G05 的预期行为 |
|---|---|---|
| T1 | “阿斯旺太折腾了，我不去了” | 理解当前放弃意图及其范围，不直接认定用户已充分比较 |
| T2 | 系统发现尚有重要差异化体验未呈现 | 在没有违反拒绝边界时，可给出一次简短、有依据的机会成本提示 |
| T3 | 用户回复“还是不去了” | 尊重取舍，不继续推荐相同理由 |
| T4 | 后续系统生成其他城市组合 | 遵守阿斯旺当前有效的排除或放弃语义 |
| T5 | 用户主动说“其实阿斯旺再给我看看” | 根据最新意图重新开放探索，而不是视为永久禁用 |

**必要判断：**

一次适度补充并不授予系统阻止用户放弃的权利。候选状态变更由既有 Trip State 规则处理；机会成本提示不能作为拖延有效状态更新的理由。

如果 T1 就包含“不要再介绍阿斯旺”，则跳过 T2 的主动补充。

### W02｜用户改道、历史需求与过期事实

**初始条件：** 用户提出天气问题，尚未获得实质回应。

| 轮次 | 事件 | 预期行为 |
|---|---|---|
| T1 | “埃及什么时候天气最舒服？” | 识别明确请求与直接回应责任 |
| T2 | 只出现天气探索入口，用户没有进入 | 不能认定天气请求已解决 |
| T3 | 用户转而探索低强度文化路线 | 当前新意图优先，旧需求保留未解决语义 |
| T4 | 系统针对旧日期启动交通核验 | 查询绑定对应适用条件 |
| T5 | 用户改变旅行日期 | 按既有规则更新有效条件并标记相关结果需重查 |
| T6 | 旧日期结果返回 | 不得作为新日期已核验事实 |
| T7 | 用户比较不同月份的舒适性 | 重新评估天气需求的相关性，可在本次分析中解决 |
| T8 | 用户已经获得充分天气解释 | 对应明确需求不再作为未解决请求反复出现 |

**工程级必要约束：**

未解决需求持续有效，但只有在与当前意图相关、确有价值且未被撤回时才重新参与优先级竞争。

不得把未点击、未执行、未解决和已拒绝混成一个业务状态。

此项归 G01 和 G05，不另立 Pending Request Policy。

### W03｜连续修改、预算变化与关键确认

**初始条件：** 用户已有一份包含重要已确认城市的有效骨架，预算是弹性意向，相关交通事实部分已核验。

| 轮次 | 事件 | 预期行为 |
|---|---|---|
| T1 | 在时间轴改变一晚停留 | 累积暂定编辑 |
| T2 | 更改城市顺序 | 保留先前编辑，更新暂定方案 |
| T3 | 操作将移除已确认城市 | 立即就地提示影响，原有效骨架保持 |
| T4 | “如果预算加一万呢？” | 进行假设比较，不自动应用预算变更 |
| T5 | “确定提高预算，重新看看方案” | 根据用户明确意图及状态规则更新相应条件 |
| T6 | 相关交通工具返回超时 | 保留事实未知，不伪造核验 |
| T7 | 用户决定接受带待核验条件的方案 | 按权限记录价值选择；事实仍待核验 |
| T8 | 用户拒绝另一项重要修改 | 不应用被拒绝变更，保留相应有效方案 |

**产品级通过条件：**

全过程中暂定与有效方案不混淆，明确硬约束不被放宽，状态改变不会使过期事实继续冒充有效结论，未受影响的决定保持有效。

## 3. 规则冲突审查与解决

### RC01｜明确请求优先 vs 主动核验

**冲突：** 当前用户正在问 A，但系统发现 B 也存在重要事实缺口。

**裁决：** 先判断 B 是否真实阻断 A。若没有，优先服务 A；B 可成为次级行动，或在当前任务真正需要时再核验。

不能因为系统发现更多缺口，就无限扩展用户眼前的任务。

### RC02｜主动帮助认知 vs 尊重放弃

**冲突：** AI 认为用户可能错过某种有价值的体验，但用户已经表示不去。

**裁决：** 不以认知不足否定放弃。只有信息确实重要、尚未提供、与当前取舍有关且未违反停止讨论边界时，才允许有限机会成本提示。

同一理由不重复劝说。

### RC03｜降低交互成本 vs 必要确认

**冲突：** 用户明确要求修改重要已确认城市，但二次确认会增加操作成本。

**裁决：** 保留影响说明及必要授权；通过就地展示实际变化和支持一次有效确认降低摩擦，而不是取消必要保护。

### RC04｜主动查询 vs 工具成本与不确定性

**冲突：** 存在潜在信息价值，但查询结果可能不可靠，或当前并不需要精确事实。

**裁决：** 只有在当前决策相关、必要条件足够、数据能力支持且预计价值合理时才执行精确核验。其他情况可提供合适的概略信息、保留未知或暂缓。

### RC05｜历史未解决需求 vs 当前新意图

**冲突：** 旧问题尚未完成，但用户已经开始新的明确任务。

**裁决：** 新意图原则上优先；旧问题保留有效性，但不自动抢占主行动。只有相关性恢复且具有实际增量价值时才重新竞争。

### RC06｜用户直接编辑 vs 系统持续重新规划

**冲突：** 地图每次操作都可能改变骨架，系统是否应立即完整计算和解释？

**裁决：** 一般编辑可累积暂定变化，延迟到相关决策点统一分析；重大冲突与权限阻断需要及时提示。状态维护与自动重规划不能混同。

### RC07｜已有事实结果 vs 最新状态

**冲突：** 工具结果本身有效，但所依赖的旅行日期或条件已经被修改。

**裁决：** 保留结果自身来源与原适用范围，不将其用于不符合条件的新决策。必要时重新核验。

### RC08｜任务闭环目标 vs 用户继续探索

**冲突：** 已有足够比较依据，但用户仍想了解其他候选。

**裁决：** AI 可以适度说明当前已能够比较的选项，并提供可选入口，但不得将进入比较或确认当作强制流程。若用户明确继续探索，应尊重新意图。

**审查结果：** RC01～RC08 可以由既有 G01～G05 协同裁决，不需要新增独立运行规则。

## 4. K01～K06 风险的正式验收要求

| 风险 | 工程必须满足的行为 | 关联测试 |
|---|---|---|
| K01 上下文重复真相 | G01 不新建一套权威业务状态；优先引用有效 State 与 Context | S02、F03、M05 |
| K02 行动失效 | 行动资格在选择和关键执行前校验；条件变化后重新检查结果适用性 | F06、M05、X02、X03 |
| K03 价值与打扰冲突 | G03 与 G04 联合考虑价值和交互成本 | S03、X01、X09 |
| K04 历史需求重复回归 | 需求连续存在，但恢复须检查相关性、价值和撤回状态 | F07、M02、X01 |
| K05 Action 层级混淆 | 区分决策目标、内部操作、执行状态与呈现入口 | S05、S07、X10 |
| K06 不主动等于不回应 | 无新增推荐时仍履行明确回应责任 | X01、X10 |

K05 的分类约束尤其重要。

首版优先区分五类**决策行动目标**：认知探索、事实核验、计算比较、必要澄清、关键确认。

状态处理、结果交付、暂缓恢复和执行反馈属于横向能力，可以服务多个目标。不要直接把此前 A1～A7 工作标签机械转换成七个平级执行器。

| Forbidden Behavior | 不得出现的越权、过度追问、误核验等行为 |

### 5.2 完整示例：F01-A

**Case ID：** F01-A

**初始条件：** 阿斯旺只是普通候选；用户曾表达文化兴趣和交通顾虑；没有明确的停止讨论要求；尚缺少可能影响当前取舍的重要体验参照。

**触发输入：**

“阿斯旺太折腾了，我不去了。”

**可接受行为：**

- 识别用户当前明确的放弃意向。
- 按已有状态语义处理该候选，不擅自改写其他已确认决定。
- 如果确实存在此前未提供、且与当前取舍密切相关的差异化体验信息，可提供一次简短、客观的机会成本说明。
- 允许用户直接结束该话题，不以继续探索作为生效条件。

**禁止行为：**

- 要求用户先了解全部阿斯旺景点才能放弃。
- 因为存在认知缺口，擅自保持其为已选择城市。
- 将“再了解一下”设为必须完成的流程门槛。
- 在用户再次拒绝后持续推荐相同内容。
- 使用无依据的价值评价或夸大交通可行性进行说服。

**状态要求：**

保留有效放弃或排除语义及相应范围；若用户尚未确认重要方案修改，则保持原有效决定直到满足授权条件。具体转换遵守正式 Trip State Schema。

**追踪：** NAP-P02、P03、P05；G01～G05；K03、K06；INV-01、INV-06、INV-10；PRD A01、A02、A03。

### 5.3 如何判定测试结果

测试应区分三类判断：

**硬约束合规：** 是否发生越权、硬约束破坏、假设覆盖有效状态、虚假核验、旧条件冒用等行为。出现即作为关键违规单独报告。

**行为适配性：** 是否回应当前需求、选择了合理 Action、避免无必要澄清、正确处理主次与跨轮次连续性。允许多个等效的合理行动。

**用户价值：** 用户是否更容易理解选项、减少自行搜索核验与重复规划、理解方案得失并完成关键决定。这一层必须通过后续用户测试评价，不能仅凭模型评测推断。

不得用未经实际测量的统一分数或模型自报置信度代替上述判断。

## 8. 全局设计约束

所有正式实现均应遵守：

**AI 主动承担能够可靠完成的决策准备劳动；用户以最低必要交互成本，逐步形成自己理解并认可的旅行选择。**

行为质量优先于行动数量；有效事实优先于流畅生成；必要授权优先于自动推进；用户当前真实意图优先于系统机械完成旅行骨架的目标。
