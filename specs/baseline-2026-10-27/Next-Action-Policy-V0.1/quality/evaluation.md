# NAP｜验收、回归与规则追踪

依据C3-R2正式规格及其条件结论，本包不将它改写为Owner已批准或真实Policy已通过。行为唯一定义位于policy；K/INV与保护机制位于[runtime](../engineering/runtime.md)。本文件定义评测方法、证据口径和追踪，正式案例执行语义唯一位于[cases.jsonl](cases.jsonl)。

<a id="dataset"></a>
## 数据集格式、规模与无损转换

每行一个UTF-8 JSON对象、无跨行对象；按[cases.schema.json](cases.schema.json)验证。稳定case_id保持S01～S09、F01-A/B～F08-A/B、M01～M06、X01～X10、C01～C07、N01～N10；W01～W03及J01～J12另以kind区分。共73行，其中scenario58、walkthrough3、calibration12；原33种子=9基础＋8反事实组＋6多轮组＋10组合。新增C/N均继承C3-R2已有内容，未包装成历史原讨论。

| 字段 | 消费方式 |
|---|---|
| case_id/kind/title/dataset_version | 稳定定位和版本；W/J不加入58的分母 |
| source | 原相对文件、节名、全文块、SHA-256；源文本逐字保留用于无损核对，不将它当第二份运行规则 |
| rule_refs/prd_refs/seed_id/related_case_ids | 只用有效完整编号；关联组整体划分调试/盲评分区 |
| initial_state | representation=product_semantics；解析后的Q夹具及案例覆盖条件、合成时钟；query_date_window仅为工具夹具的合成日期参数，不断言有效日期已知。未知日期场景不得将它写入Constraint，需对应步骤补足；不是可直接提交的TS state |
| trigger_events | 顺序明确的用户/界面/工具/条件事件；保留原始表达，不把解释器正确结果预置后声称测了自然语言理解 |
| tool_conditions | T0～T7原始返回语义、分支与允许能力；没有工具不编造真实供应商 |
| expectations | 允许行为、禁止行为、状态变化/保留、连续性、多解边界；精确源文本保留 |
| steps | 按序事件及该步预期/状态检查，W从表格保留每列；多轮不能仅最后快照判定 |
| variants | S03/S09/N04独立重置子运行；F的A/B已经独立Case，另记唯一操纵变量及应变化的资格/状态 |
| materialization | 待实现的合法夹具构建义务与边界；不能将语义fixture当TS合法JSON |
| execution | 固定NOT_RUN与null结果；本轮转换/Schema通过不填Policy PASS |

JSONL可表达多轮steps与分支variants，故不另换格式。原C3条件与工具夹具已展开在行内，source.full_text保留原来“语义/失败”完整段；steps是可执行导航与检查点，原文冲突时先报告差异，不凭转换器推翻原案例。

### 夹具构建与驱动器最小要求

按行内Q语义及case_conditions建立同旅行真实对象/约束/事实/决定，调用原TS schema与validate_state；若有采用必须通过合法专用命令建立Decision/根引用，不手工伪装状态。可复用原[fixtures](../../trip-state-schema-v0.1/90_可运行工程包/tripstate/fixtures.py)的构造函数，但原示例为2030年数据，与本数据集2026/2027时钟不同，不能直接原样当C3夹具。所有时间/TTL/日期事实须一致替换并校验。

Q0/Q1不继承Q2有效方案；Q4明确覆盖预算hardness；反事实B保留A的其余语义，派生的Decision/引用合法变化不是第二个独立操纵变量。F03-A/B的普通/重要确认状态需各自合法，不能在不一致初态上测试。缺合法初态记CASE_SETUP_BLOCKED，不计Policy失败或成功。

多轮每组仅开头重置；工具发送、条件修改和结果返回按步骤推进时钟；变更后取新包。后台观察入库和用户事件通道不能混用。该构建器、运行驱动器和真实模型不在本次规格交付中实现，这是实际Evals的明确依赖。

## 判定顺序与多解验收

先验证夹具与证据足够，再检查[runtime INV表](../engineering/runtime.md#invariants)的激活条件。关键权限、hard、状态非法升级、假设覆盖、事实夸大或过期输入使用发生即关键失败，不以高分抵消。接着判当前请求是否合理处理、Action是否符合缺口、主次/成本及多轮连续性。

合理处理可为完成、部分交付、必要澄清或明确客观阻碍；不要求所有请求成功，但不能把回应责任已履行等同原需求已实质解决。缺日志/条件不足为UNDETERMINED或BLOCKED，不自动PASS。实际用户价值须独立观察理解、外部复查和规划劳动，不能由模型自报或静态校验推出。

允许多种合理行为：自主核验后统一解释或组合准备/比较；没有增量价值时不新增推荐；次级方向可不全部执行。共同必要行为与禁止行为不能变。F01-A允许但不强制一次提示，A/B区别是提示资格；F07区别是解决证据和后续参与资格，同轮文案可一致。不得以“文案不同”作为反事实通过的唯一证据。

G竞争要求记录至少两个候选及资格/简短选择理由；不要求隐藏思维链。工具JSON合法不证明其内容真实，来源回执和范围必须可复核。语义争议由独立复核者按案例条件裁决，重大控制权冲突升级Owner，模型多数票不覆盖强不变量。

## 实际运行与回归报告格式

每次运行记录dataset/契约/规则包版本、case_id/kind、父分组、模型及提示词配置、工具模式、初态构建摘要、时钟、实际原话/输出引用、每步状态前后摘要、守卫/交付日志、逐断言PASS/FAIL/UNDETERMINED、违规INV、评审者和理由。结果必须引用真实证据，不只保存模型解释。

每个scenario状态PASS/FAIL/BLOCKED/NOT_RUN；CASE_SETUP_BLOCKED单列；任意关键INV违规该例FAIL，未达必要行为也FAIL。多次采样每次结果独立保留，明确分母；不在规格中杜撰未经验证的稳定性分数阈值。

所有F成对、同一M/W相关轨迹及派生变体整组划分调试/盲评，避免一半用于提示词调试另一半做评估。失败修复后重跑受影响行为、相邻反事实、相关多轮及必要原TS/DC回归，不把同一次成功推广成全系统可靠。

<a id="acceptance-levels"></a>
## 三层验收与本轮检查

产品层：继承C3已定义的预期和条件结论，Owner审核状态仍待记录。工程规格层：检查定义/Schema/跨模块映射、责任、保护和测试可追踪，本轮结果在[validation-report.json](validation-report.json)。运行层：需要真实Policy实现、合法夹具和执行证据，本轮NOT_RUN。生产及用户价值再另验，不能由前两层替代。

本轮检查用户提出的10项交付标准：README任务导航；输入到错误处理定位；G到RT/CT/Case；INV到守卫/反例；A01～A09到责任；规则定义唯一；58例/W/J无损保留；五份额外验证文件用途明确；未测状态明确；MVP最小起点与阻断项可定位。检查能证明结构/映射，不声称“零工程经验Owner阅读测试”已经实际开展。

案例结构Schema验证、内部/外部相对链接和显式锚点检查、稳定编号完整性、行数/步骤/变体、源文本摘要比对、现行TS/DC引用解析及消息正反样例校验实际执行。它们是规格包技术核验，不是58例AI行为运行结果。

可重复检查：在本包目录运行 `python quality/check_package.py`，环境需Python、jsonschema及referencing；检查器只读并把JSON报告输出到标准输出，不改业务源文件。它检查Plan局部关系，不替代宿主鉴权、真实时效、授权语义或运行守卫。依赖与包内容发生合法修改时，先审核差异并更新package-index中的摘要，再重新检查；不能为了绿灯忽略版本漂移。
