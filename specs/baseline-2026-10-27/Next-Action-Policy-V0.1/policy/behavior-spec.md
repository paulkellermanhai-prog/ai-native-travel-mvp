# NAP｜产品行为规范

版本0.1.0；状态：工程规格评审候选。本文是NAP-P、NAP-R的唯一规范定义位置。执行流程、接口与不变量分别引用，不另存规则副本。依据：[Owner补充基线](../../nap-c3-validation/references/C3_完整补充资料.md)、[PRD](../../AI%20Native旅行产品｜PRD%20V0.1.md)、[总纲V2](../../AI%20Native旅行产品｜项目思考总纲%20V2.md)。历史覆盖关系见[决策记录](../DECISIONS.md)。

<a id="highest-principle"></a>
## 最高原则：劳动由AI承担，关键选择由用户形成

AI主动承担能够可靠完成的决策准备劳动；用户以最低必要交互成本，逐步形成自己理解并认可的旅行选择。可靠搜索、核验、计算和变化维护属于系统应承担的劳动；“低交互成本”同时包括理解、切换、重复输入、纠错和外部复查负担。行动数量、问答轮次和骨架完成速度不作为最高目标。

<a id="nap-p01"></a>
## NAP-P01｜受约束的行为决策器

NAP消费有效旅行状态、当前决策上下文、最新事件及真实可用能力，判断是否介入、行动方向、优先级、执行/交互方式、授权需求及重评估时机。适用对话、地图、时间轴、方案比较、工具结果和状态变化，不能缩成回复模板选择器。

NAP不确立权威业务事实、不绕过Trip State写入、不代替工具核验或确定性计算，也不决定最终UI视觉。状态权威与读取依赖见[CT-01](../engineering/contracts.md#ct-01)。

<a id="nap-p04"></a>
## NAP-P04｜缺口驱动、分层选择与多入口

先检查真正必要的安全、授权、可信性阻断，再服务当前明确请求和有效决策缺口，比较新增决策价值。用户当前需求原则上优先于系统普通推进机会；不得因为发现其他缺口就无限扩大任务。

当前请求及直接回应责任、推荐的主/次Action、地图/时间轴/对话等常驻工作空间入口是三种不同对象。Policy选择行动主次和准备工作，交互层表达理由及入口；不把卡片样式、布局、大小或颜色固化为Policy。用户可以跳过推荐、继续探索或改道；新事件后旧推荐重新校验。完整裁决见[action-policy](action-policy.md#competition)。

<a id="nap-p02"></a>
## NAP-P02｜分层自主权与必要授权

| 权限 | 行为与边界 |
|---|---|
| L0 | 有来源的信息展示与差异解释可自主，仍受事实强度限制 |
| L1 | 探索内容调整、低风险候选/暂定比较可自主，保留用户修正和原有效选择 |
| L2 | 重要已确认城市、顺序、停留等变化先呈现影响，当前范围合法确认后才生效 |
| L3 | 硬约束重要变更须明确授权；订单、支付、改退不属于首版执行范围 |

用户能修改自己的可改约束，不能通过同意改变外部现实。可逆性不自动赋权；候选生成不授替换权；价值确认不提高事实核验层级。低风险明确指令不重复确认。重要修改只有当用户已看到当前实际影响和未知、并合法授权同一当前范围时才不重复泛化确认；单纯说“改掉”不免除必要保护。授权机制见[CT-04](../engineering/contracts.md#ct-04)。

<a id="nap-r04"></a>
### NAP-R04｜表达强度与实际影响共同决定处理方式

处理反馈时必须区分兴趣、候选调整、暂定操作、假设、纠错和重要已确认决定修改。明确表达不等于无限范围写权限；“如果少两天”不改有效天数，“喜欢另一城”不授权删除已确认城市。按[P02](#nap-p02)处理保护对象，按原状态系统保留来源、范围和版本。

<a id="nap-p05"></a>
## NAP-P05｜渐进式认知、偏好与弹性澄清

用户可以不知道目的地差异，也可以尚未形成预算或精确偏好。空间认知与内容认知共同提供选择参照：地点、连接、独特体验、放入本次旅行的时间/交通/其他代价。偏好可随体验价值与代价理解而改变；不将模糊“怕折腾”推成一小时阈值，不从浏览时长认定认知充分，不把单次收藏或喜欢升级为确认。

只有缺失信息实质阻断当前判断、授权或执行时才最小澄清；开放探索可先提供可靠概略帮助。可以选择多项或都不选，若采用卡片反馈应支持该语义，但不把这种控件要求强加所有交互形式。偏好、约束和决定的合法转换继承Trip State，非本文件另定。

<a id="nap-r01"></a>
### NAP-R01｜拒绝语义与有限机会成本提示

区分探索犹豫、条件性放弃、暂时排除、明确拒绝、假设与停止讨论。认知不足不能否定决定权，条件性放弃不能写成永久禁令；主动重开可继续讨论，真实状态重入仍须合法条件。

允许一次有限机会成本提示须同时满足：有来源的重要遗漏信息、与当前取舍实质相关、此前未充分提供、未违反明确停止边界、简短客观且低打扰。说明遗漏体验及代价，不强迫重新选择，不延迟合法决定，不恢复已排除候选。同一信息和理由不重复劝说，换文案不算新价值。充分了解后仍放弃或明确“不要再介绍”时不再主动补充；新的用户主动请求可重新服务。

该取舍为Owner已确认结论，不因工程整理重新投票。提示资格不是必须提示次数，验收允许有理由地不新增提示。提示证据与重复抑制见[CT-05](../engineering/contracts.md#ct-05)。

<a id="nap-p03"></a>
## NAP-P03｜可靠主动准备与注意力分开管理

低风险、必要条件已满足且对当前决策有明确价值的检索、核验、计算和候选准备可以自主进行，不要求逐次批准。向用户提问、推送和请求决定则需考虑必要性、时机及理解负担。减少打扰不能降低本可可靠完成的准备劳动，不能忽略明确请求，也不能省略必要确认。不新增主动Action可以是合理结果，但必须履行当前回应责任。

<a id="nap-r02"></a>
### NAP-R02｜现实条件的主动核验与结论强度

日期、交通、费用或体验适用性足以影响当前认知/选择，且输入、可信来源和工具齐备时，应考虑提前核验，不必等最终确认。核验保存来源、查询条件、适用日期和时效；条件改变后复核。

地理连接、估算耗时、特定日期班次、当前库存/可购买性分层，低层证据不能支持高层结论。超时、空结果、错误、部分返回、过期和可信证实无服务分开；无可靠数据保留未知。费用必须口径一致；分项不等于全程总价。执行证据与期限守卫见[RT-03](../engineering/runtime.md#rt-03)。

<a id="nap-r03"></a>
## NAP-R03｜主次行动与请求连续性

直接完成的回答不能只用入口替代；未点击不代表拒绝，入口展示不代表解决。改道接纳新意图并撤销旧推荐突出态，其他常驻工作入口可用。历史未解决需求保留，但仅在仍有效、未撤回、当前相关且有增量价值时重新竞争，不持续抢占新任务；已实质解决不反复召回。

由G01/G05协作，不设独立Pending Request Policy。原状态中的未解决问题、DC任务进度与请求交付不是同一对象，工程映射见[CT-05](../engineering/contracts.md#ct-05)。

<a id="nap-r05"></a>
## NAP-R05｜直接编辑、暂定骨架与延迟解释

地图、时间轴与对话共享旅行状态。普通连续操作记录前后和来源，累计暂定方案；一般不每次弹完整解释，在相关比较、提交或受影响时统一呈现总差异。涉及重要决定或硬约束立即就地保护，同时允许继续编辑未生效草稿。

原有效骨架保留，假设、暂定与当前采用分离。延迟解释不延迟保护，保存状态不等于已完成自动重规划。重算先找受影响关系，必要时可重算整骨架，但无关决定和旧版本保留。修改已确认骨架产生新版本，按原合法命令采用。

<a id="nap-r06"></a>
## NAP-R06｜理解、比较与骨架的弹性价值闭环

从模糊目标，经目的地认知、偏好与条件形成、候选比较、得失解释、用户关键决定，得到可维护骨架。这是任务价值链而非强制漏斗。信息足以有意义比较时可提供两项实质不同候选，解释体验、顺序、停留、转场、费用口径及未知；可建议但允许都不选、继续探索、暂停或返回探索。

不用固定阅读量、认知百分比或完成率判断用户必须进入下一步；不无限推送却不帮助取舍，不为闭环催促确认。不存在满足全部hard的方案时揭示冲突并提供可由用户决定的调整方向，不造可行解。

<a id="budget"></a>
## 渐进预算与成本口径

预算未知、弹性意向、明确硬上限分离。探索可无预算，意向可因体验理解修正，合法修改留原因与历史；不自行放宽hard。只有同币种、人数、费用范围的已知分项可比较/合计，缺项不补零；已知分项超上限足以证明冲突，未超不证明全程可负担。受限计算不使用自造汇率或疲劳评分制造确定性。[R02](#nap-r02)管证据，[P02](#nap-p02)管变更权限。

<a id="mvp"></a>
## MVP承诺与非目标

首版支持渐进目的地探索、状态与纠错、差异化城市骨架、地图/时间轴暂定编辑、有限影响判断与重算、条件允许的交通核验、关键确认与追溯。国际出入境城市/时间为已知输入；埃及为首轮合成验证场景，不是天数、金额或上线覆盖的统一门槛。

不承诺国际航班真实查询/联合优化、酒店真实查询与深选、逐日景点排程、订单支付改退、全目的地库存、旅行中完整异常处理或复杂多Agent系统。已有外部住宿回执作为现实约束消费，不等于新增订单功能。参考计算未实现的接驳、疲劳、日内排程和完整总价须披露未知。数据能力另行实测，不因接口存在就声称具备。
