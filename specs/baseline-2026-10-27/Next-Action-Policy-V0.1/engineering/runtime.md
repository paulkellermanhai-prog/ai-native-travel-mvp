# NAP｜运行机制、保护与失败处理

本文是RT运行条款、K01～K06、INV-01～10的唯一工程规范定义位置。[行为规则](../policy/behavior-spec.md)、[G机制](../policy/action-policy.md)和[契约字段](contracts.md)通过引用使用。本文为待实现要求，不是运行成功报告。

<a id="rt-01"></a>
## RT-01｜一次决策的执行边界

1. 宿主鉴权并读取当前Trip State，DC解释器据原始事件定位多任务、分支和焦点；调用原open_turn。无足够上下文时按原受限协议处理，不能先靠NAP生成任务再循环组装。
2. 对本轮当前任务调用assemble，按需page；跨包必须同旅行、当前revision/摘要和有效期。保护集合不裁掉，正文交付状态真实记录。加载CT-05已确认运行历史，缺失则按其降级。
3. 执行G01理解，G03生成候选，G02校验，G03/G04联合选择；保存不可变DecisionPlan及其内容摘要。模型的权限/资格说法不作为宿主证明。
4. 校验Plan结构与跨引用：basis逐项匹配原包，所有action引用本包合法task，steps引用存在、唯一且无环；不合格计划返回错误而非尽力执行部分危险内容。
5. 宿主将合格Action记录为eligible；UI显示和普通response交付分别记录，主Action最多一个需要占用当前注意力的方向；prepare可以与其组合。
6. dispatch时重新读当前State/DC和授权，按RT-02原子认领步骤；有用户/工具等待则返回等待状态，不占一个长期阻塞请求。
7. 结果按CT-03/04受控处理；业务revision改变立即使旧依赖计划过时。G05读取新依据重新决策，旧候选不自动重放。

多任务竞争可以共享一次事件解释，但每个Action绑定自己的包和task，不将不同revision摘要拼成一份“当前上下文”。例：先查交通的观察入库会改变revision；后续比较必须新组装/新计划，保留同task及关联行动历史，不能沿用旧basis继续写。

<a id="rt-02"></a>
## RT-02｜Action生命周期、依赖与执行前再校验

ActionRecord由宿主保存并转换，不属于TS业务对象。结构见机器Schema；`phase`由程序维护，模型输出Plan不带已通过的phase。运行成功也不代表用户已决定或外部事实全核验。

| 当前phase | 事件/守卫 | 后续phase及语义 |
|---|---|---|
| proposed | 完成CT结构和G02确定性检查 | eligible；失败为blocked，不执行 |
| eligible | 确认/澄清确需用户输入 | waiting_user，保留原方案和当前范围 |
| eligible | 当前依赖/权限/步骤条件通过且认领成功 | running |
| eligible / waiting_user | 依赖或授权过期、旧入口、状态改变 | stale，旧执行资格作废 |
| waiting_user | 新真实反馈且原basis仍有效、范围授权通过 | eligible或拒绝时cancelled；若新输入需新依据则新决策 |
| running | 完整目标步骤完成且结果可用 | succeeded，仅指该Action目标；请求交付另判 |
| running | 仅部分准备/交付完成 | partial，保留缺项，由新计划决定后续 |
| running | 已知执行失败 | failed，保持原业务状态及真实失败记录 |
| running | 返回时依赖已变化 | stale，结果只留历史，不支持当前结论 |
| proposed / eligible / waiting_user | 用户合法取消该动作或替换焦点使其无关 | cancelled；不解释为撤销业务决定 |

blocked/partial/succeeded/failed/stale/cancelled均为本次Action记录的终结状态，需要继续时新decision/action ID关联旧记录；不原位复活旧资格。运行中取消是尽力中止；若提交结果不确定先记录NAP_EXECUTION_UNKNOWN并查原幂等结果，不能宣称已回滚。尚在运行且未定结果时phase仍running，error_ref指不确定诊断，不凭超时认业务失败。

每个step执行前重新检查：主体/旅行/工作区/runtime代次、Plan摘要、包版本/TTL/事实适用性、当前约束、停止/撤回范围、能力输入及前驱结果。DAG依赖完成只是必要条件；前驱入库改变revision后必须新计划。未显示的重要差异、未获必要范围授权、正文未交付完整都不能通过先执行后解释补救。

`change`只提交当前原TS请求，传递原Runtime/Store守卫；ask/confirm不自动提交。原Grant属于宿主，不能保存在可恢复计划里继续使用。UI点击只是新事件，不是授权凭证。无可靠重入条件遵循[CT-04](contracts.md#ct-04)，不能用高价值推荐绕开。

<a id="rt-03"></a>
## RT-03｜工具结果、条件变化与失败恢复

结果接收先核对可信来源、completion/action/step绑定及原查询摘要，再检查当前适用性。即使原查询正确，日期改变、事实到期或新hard进入都会使原计划失效；历史观察保存与当前可使用分开。消费时再次看时钟，不以revision没变延长事实生命。

| 工具状态 | 可记录与交付 | 恢复要求 |
|---|---|---|
| result | 仅覆盖可信字段及适用层级 | 结果入库后新Context；不能自动提高到库存/购买 |
| partial | 实际字段、缺项、影响与仍未知部分 | 新证据补足后再提高结论强度 |
| empty | 本查询未找到，不能证无服务 | 有价值时换可靠来源或补条件 |
| timeout / error | 原始失败，失败不会覆写仍可用旧观察 | 默认不自动重试；条件/工具恢复后新决策；不让用户重复给已有参数 |
| no_service | 有来源的指定日期/区段无服务 | 改条件/服务范围再判断，不永久排城 |
| 相互矛盾 | 保留双方来源，相关问题与判断待复核 | 可追溯消歧；不按最后写入者为真 |

timeout由宿主注册能力的正数超时决定；本版默认一次尝试，无自动循环重试或换幂等键。只读读取可按DC三次快照机制重建；业务写入/确认不自动重基。下游计算失败保留stale，不复活旧verified；用户原价值选择只待复核，不自动撤销。

工具观察与用户变更是不同信任通道，按[CT-03](contracts.md#ct-03)处理。真实提供方、真实性、库存与生产事务需独立验收，Schema通过不等于真实世界正确。

<a id="rt-04"></a>
## RT-04｜回应、改道、拒绝与多轮连续性

服务当前需求时可以先自主准备再交付。响应内容发送和UI呈现回执分开；收到真实交付回执后才记录delivery。主推荐突出态在改道后退出，常驻入口不受推荐有效性约束；旧Action入口点击仍要重验。

response是待交付内容，不因decide返回就已呈现。宿主按(主体,trip,workspace,decision_id,response内容摘要)去重投递；同内容重试不再主动推送，UI已呈现回执才形成delivery。若同一内容已经放在response中，不再以deliver步骤重复交付；步骤仅用于尚未交付的后续结果。投递回执丢失先查既有记录，不以重新发消息取代查证。

当前请求、Action完成、DC进度、TS OpenIssue是四种不同粒度。实际交付覆盖判断由G01/G05结合CT-05日志和原请求做，不能因为查询成功/按钮出现就关闭请求。停止/撤回按对象范围解释并记录来源；未点击或暂缓不能被当撤回。用户主动重新打开可以恢复讨论，业务重入和采用仍按当前条件确认。

拒绝后旧提示无新增价值不再主推；只有用户当前主动请求或真正相关的新条件才可重新竞争。必要机会成本提示的合法条件引用[R01](../policy/behavior-spec.md#nap-r01)，实际呈现后记录语义主题和来源，按同理由而非只按哈希抑制重复。日志缺失或语义不确定时不借“可能新信息”重复劝说。

连续编辑累积未采用plan/宿主草稿，业务采用引用不动；相关分析才统一解释。对重要决定或hard的即时保护不等于阻止继续编辑。跨入口新条件先更新其合法范围，再使草稿基准待复核，不能最后写入者抹去另一路输入。

<a id="rt-05"></a>
## RT-05｜幂等、并发、恢复与可观测性

| 边界 | 最小实现要求 |
|---|---|
| decide | 同主体/工作区decision_id＋同请求摘要返回原Plan；同ID异内容NAP_IDEMPOTENCY_CONFLICT。旧Plan返回不等于仍可执行 |
| dispatch | 原子认领(主体,trip,workspace,decision_id,action_id,step_id)，唯一键＋状态比较；防双击/双Worker重复执行。内容摘要不同拒绝，不换键绕过 |
| complete / feedback / observe | completion_id/feedback_id/observation_id分别幂等；同ID不同内容拒绝，重复回执不重复入事实/呈现/记录 |
| 状态写 | 原expected_revision、请求摘要、Grant、提案范围及幂等守卫；成功/待确认/拒绝原样传播。多个命令按原TS原子单位提交 |
| 提交回执丢失 | 查原幂等缓存/审计再同步运行记录；执行结果未知不盲重试。外部副作用本版禁用，不声称跨服务exactly-once |
| 并发输入 | 新revision使旧包/计划stale；新原话不混用旧轮次。重要提交不自动合并/重放，需当前预览与授权 |
| 恢复 | DC恢复现有任务/视图/草稿；NAP单独恢复已确认运行日志，重读最新State；不恢复旧Packet/Grant/确认token/可执行资格 |
| 日志保存失败 | 不回滚已成功业务、不重复展示提示；说明未确认保存。只有保存回执后宣称可恢复；见CT-05 |

日志至少包含关联ID、原始事件/回执定位、Plan和查询摘要、状态版本/时效、资格结果及理由码、工具实际状态、原提交结果、呈现/交付回执、INV违规与恢复动作；不记录密钥、付款资料或完整用户原文到不受控日志。原文与隐私保留由既有宿主政策管理，日志不公开给跨主体会话。

实现可用数据库唯一约束/事务或等价原子存储，不在规格指定品牌。跨NAP日志与TS业务不能假设分布式事务：先用原幂等结果查证再对账，运行记录单独失败不得重复业务。生产崩溃/多进程争用仍需实测，当前DC进程内锁不是生产证明。

<a id="rt-06"></a>
## RT-06｜确定性检查与模型判断边界

| 确定性可检查 | 需模型/人工语义判断，程序不能自证 |
|---|---|
| Schema/引用/同trip/同主体、revision/摘要/TTL、实际事实级别、DAG、幂等、原命令权限与确认绑定 | 用户真实意图、拒绝/条件的对象范围、是否同一理由、是否有重要遗漏、请求是否实质答完 |
| 活动hard与既有计算覆盖范围内的已知冲突、必需参数是否存在、提供方是否注册 | 信息的主观价值、概略帮助是否足够、问句是否必要、当前主次是否适配 |
| 真正交付/保存回执是否存在、原话区段是否逐字匹配 | 模型/用户是否理解、原话是否真的授权该影响、真实提供方事实是否正确 |

语义不确定不自动提权/完成；可降级、保留未知或最小澄清。模型自报高置信、来源字符串或统一分数均不能替代这些证据。

## INV-01～INV-10｜强制不变量的唯一规范定义

适用条件先成立再判失败。关键违规不以文案、满意度或高综合分抵消。下表同时给出工程拦截和具体失败测试，评测文档仅引用。

| ID | 不变量定义及适用条件 | 保护与失败处理 | 正/反测试 |
|---|---|---|---|
| <a id="inv-01"></a>INV-01 | 推断、兴趣、收藏、候选、暂定不能未经合法转换升级用户确认 | CT-04原权限/转换；不合格写拒绝，状态保持，记录违规 | S02/S05/F03-A/B、N07合法升级对照 |
| <a id="inv-02"></a>INV-02 | 活动hard和重要已确认决定不得静默覆盖 | RT-02＋TS确认/原子守卫；阻断写入并解释影响；用户可合法改自身条件，不能改外部现实 | S08/X04/X06/N07/N09 |
| <a id="inv-03"></a>INV-03 | 事实/计算结论不超过来源、条件、口径与层级 | CT-03可信适配器、RT-03；拦截夸大交付，保留未知和原观察 | F08-A/B/N04/N05/X07 |
| <a id="inv-04"></a>INV-04 | 依赖变化后执行及结果使用前必须重验适用性 | RT-02/03版本、时钟、摘要检查；旧计划stale，重读不重放；旧结果仅历史 | X02/X03/N03/N08 |
| <a id="inv-05"></a>INV-05 | 当前明确请求必须合理处理，入口不等于回应完成 | CT-02 response、CT-05真实交付；缺交付不记完成；允许部分处理/必要澄清/说明阻碍但不声称已成功解决 | X01/X10/F06-B/M02/N02 |
| <a id="inv-06"></a>INV-06 | 拒绝、停止和条件放弃按各自范围生效，不持续劝说 | R01资格、CT-05历史和RT-04；违规推送取消，合法决定不延迟；有限提示不授反复许可 | F01-A/B/F02-A/B/N06/X05 |
| <a id="inv-07"></a>INV-07 | 假设、暂定与有效采用保持分离 | 原hypothetical/plan/根采用守卫，未确认不生效；后续合法应用允许新版本 | S06/F04-A/B/M03/X08 |

| <a id="inv-09"></a>INV-09 | 改道不清有效需求，已解决不重催，旧需求不无故抢新题 | CT-05交付/撤回与RT-04资格；当前任务优先，纠正误标；撤回/失效按来源结束或重评 | F07-A/B/M02/C06/N02 |
| <a id="inv-10"></a>INV-10 | 降交互成本不能省必要保护，可靠主动工作不能变成过度干预或反复审批 | P02/P03＋RT-02/04；重要确认不省，低风险准备不反复要许可；是否多余需具体语义判断 | C07/S08/N06/N07/X09 |

在生成前可阻断写；在呈现后发现违规则记录实际失败、停止重复并纠正表达/依据，不用删日志伪装未发生。已发生错误业务提交需按原用户授权/纠错流程处理，不能以“自动回滚”再次越权。确定性守卫不能证明语义正确，后续必须运行对应模型/多轮测试。
