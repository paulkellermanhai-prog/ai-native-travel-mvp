2026-10-24/U06：持久检查点接口/迁移/恢复契约已补齐，运行合同现为 0.2.0。恢复字段、错误和协议详见 [恢复规格](05_持久检查点与跨会话恢复规格.md)。

日期：2026-10-23。接口前缀 `/runtime/trips/{trip_id}/`。当前 [api.py](../90_可运行工程包/context_runtime/api.py) 是本地 dispatch，不是已部署 HTTP 服务。

## 1. 接口清单及完整机器合同

| POST 路径 | 请求 Schema | 成功响应 | 作用 |
|---|---|---|---|
| turns | open-turn | turn | 验证并注册本轮任务理解，不写业务状态 |
| assemble | assemble | packet | 固定版本组装与首包解引用 |
| pages | page-request | page | 读取同包清单内正文并记录交付集合 |
| changes | change | 原 Trip State response | 与本轮/读取绑定后调用原 submit |
| confirm | confirm | 原 Trip State response | 校验本轮提案归属后调用原 confirm |
| checkpoints/save | scene-save | scene-ack | 持久保存焦点/视图/草稿 |
| checkpoints/restore | scene-restore | scene-restored | 找回现场并按当前状态重建 |
| checkpoints/delete | scene-delete | scene-ack | 删除现场，不删除业务状态 |
| checkpoints/list | scene-list | scene-list-result | 自动发现本主体可用现场 |
| checkpoints/status | scene-status | scene-status-result | 区分业务生效与现场保存确认 |
| checkpoints/retry | scene-retry | scene-ack | 只重试保存，不重放业务操作 |

本包 20 份当前机器 Schema 位于 `90_可运行工程包/schemas/`，9 份旧 0.1 合同保留于 legacy-0.1/。原 change-request、confirm-request、response、DecisionContext 及业务对象通过原 `$id` 离线引用，不复制/改写合同。生成字段字典列出全部顶层、嵌套、数组项和共享定义。

POST turns/assemble/pages 正常 200；变更成功 200、待确认 202、版本/幂等冲突 409、业务拒绝 422、权限 403、内部失败 500。运行层错误返回独立 error；原状态错误返回原 response，客户端按接口/形状识别，不能只判断 HTTP=200 就认为核验完成。

## 2. 字段拥有权与写入边界

| 数据 | 所有者 | 写入路径 |
|---|---|---|
| 用户意愿/候选/约束/骨架/决定/外部事实 | 原 Trip State 对象，权限不变 | 原命令/可信工具/确认链路；运行层不额外直接写 |
| 当前有效采用 | 原根 effective_skeleton_id | 原 adopt/withdraw 及原子守卫 |
| task_key/question/关系/进程 | 运行层，按主体/旅行/工作区持久；解释器输入需验证 | open-turn 与检查点，不是用户决定或新业务对象 |
| 原输入及处理响应 | 本轮运行封装，已提交的证据另留原系统历史 | open-turn / changes / confirm |
| 快照、正文、交付清单、四维注释 | 只读组装/消费运行层 | assemble/pages，禁止业务回写 |
| Actor/Principal/WriteGrant | 经鉴权的宿主 | 函数注入，不能从模型 JSON 解析 |

原话 codepoint 范围验证只证明定位，不证明原因/偏好语义。客户端无法通过添加 actor/status/verification 字段扩权；所有 JSON 拒绝额外字段。历史 source 的角色与写入原因由原 Store 维护。

## 3. 变更和确认的绑定

changes 请求包含 turn_id、packet_id、原 request；必须是同主体、同一轮、当前包、当前 revision；input.text/reference 必须与本轮事件相同。假设分支只允许创建 purpose=scenario 的 Skeleton；不能修改有效约束、采用 plan 或借由根改变假设。

重要选择须完成包正文交付。WriteGrant 精确绑定整个 change-request，过期/主体/事件/内容/版本不符拒绝。没有 Grant 的模型提案不升级用户身份；原权限决定是低风险可应用还是需用户确认。

confirm 绑定本轮真实 proposal_id，宿主确认用户行为后注入 User Actor。原程序重新验证摘要、revision、期限、范围、现实条件；旧包和旧页面不能延长确认有效期。明确用户指令已合法授权时不强制额外弹窗；内部程序校验自动执行。

## 4. 幂等、并发与失败原子性

- event_id 在主体内作为 open-turn 幂等键，同请求返回原 Turn；同 ID 异内容 EVENT_REUSE。不将旧成功返回解释为当前状态仍相同，后续组装仍取当前状态。
- changes 的幂等缓存绑定主体、turn_id、原 idempotency_key 和整个运行请求摘要（含 packet_id）；同内容返回原结果，包括成功后的重试；异内容拒绝。不能换 packet_id 偷用同键“自动重基”。
- confirm 继承原确认幂等；相同确认请求返回原最终结果，运行写入缓存同步为最终结果，不重复生成业务历史。
- Runtime 用 RLock 保护自身会话容器，原 Store 单独维护原子业务提交；两者不构成生产跨库事务。若进程在业务提交后、运行处理状态更新前崩溃，必须依赖原幂等查询/历史恢复运行视图，不再提交一遍；本地未验证宕机窗口。
- 结构/身份失败发生在业务提交前；原内部失败维持失败前状态。真实生产事务、提案和幂等结果持久化仍按原契约单笔提交。

## 5. 稳定运行错误码

| 码 | HTTP/可重试 | 语义与调用方处理 |
|---|---|---|
| ACCESS_DENIED | 403/否 | 无宿主旅行权限；不能换对象 ID 猜测 |
| NOT_FOUND | 404/否 | 资源不属于主体或不存在，不泄露其他主体信息 |
| METHOD_NOT_ALLOWED | 405/否 | 只支持该接口声明方法 |
| CONTRACT_INVALID | 422/否 | 结构/版本/额外字段错误，返回路径，不回传完整原话/状态 |
| TRIP_MISMATCH / TARGET_NOT_FOUND | 422/否 | 输入跨旅行/对象不可解析，不用相似对象替代 |
| SOURCE_SPAN / EVENT_TIME | 422/否 | 原文定位不符或输入来自未来 |
| TASK_KEYS / TASK_RELATION / TASK_IDENTITY | 422/否 | 焦点/关联/身份范围不合法 |
| TASK_CLOSED / TASK_PAUSED / PROGRESS_EVIDENCE | 422/否 | 进度转换或证据不合法，不能由 focus 结束/恢复问题 |
| TASK_NOT_RECOVERABLE | 422/否 | 会话无旧任务，不伪造跨会话恢复；允许重新定位新问题 |
| EVENT_REUSE / IDEMPOTENCY_CONFLICT | 409/否 | 同键异内容，需纠正调用，不自动换键重写 |
| REVISION_CHANGED / SNAPSHOT_BUSY / SNAPSHOT_MISMATCH | 409/是 | 重新读取/定位/组装；不得自动重放重要提交 |
| PACKET_STALE / PACKET_EXPIRED / EVIDENCE_CHANGED | 409/是 | 重建；用户授权不自动续期 |
| ASSEMBLY_FAILED | 422/否 | 种子/原组装调用失败，不返回半包；检查来源后再请求 |
| PAGE_SCOPE / TURN_MISMATCH / INPUT_BINDING | 422/否 | 读取/轮次/来源绑定越界 |
| WRITE_GRANT / HYPOTHETICAL_WRITE / INCOMPLETE_DELIVERY | 422/否 | 授权、假设或正文交付不满足；不从模型自述补证 |
| PROPOSAL_BINDING | 422/否 | 提案不属于本轮；不跨轮批准 |
| INTERNAL_FAILURE | 500/否 | 不声明成功；宿主按日志与原幂等结果诊断，不盲重试 |

原业务错误码（VERSION_CONFLICT、HARD_CONFLICT、FIXED_CONSTRAINT、CONFIRMATION_EXPIRED 等）原样继承，不在运行层偷换为成功。retryable=true 只允许重新读取的技术重试，不等于允许自动再次确认/放宽条件。

## 6. 版本与兼容迁移

现行 Trip State schema_version=0.1.0 保持字节不变；新运行协议独立 `$id`，无已发布旧运行数据，故本轮没有假造数据迁移脚本。

任何正式扩展字段/枚举都须新版本、新 `$id`、字段说明、兼容/迁移与正反测试同步；不能靠 additionalProperties 逃避。U06 已通过运行 0.2.0 补齐检查点/草稿/保留/失效与授权代次，旧请求不静默升级；持久现场不写入 Context 或 ChangeRecord，Trip State 0.1.0 不变。

读取包可丢弃重建，不能以历史包迁移代替业务数据迁移。事实/决定的历史引用不授予当前采用资格。原业务合同变更时先核对差异/回归，不用最新第三方惯例重新定义对象。

## 7. 生产接入的明确责任

宿主：鉴权、旅行访问控制、用户授权语义、模型/工具信任边界、会话隔离/释放、诊断隐私与保留。

状态服务：持久事务、提案/幂等/历史、事实可信接入、时效维护、原守卫。

运行服务：本合同任务验证/组装/版本/时效/交付、运行异常与消费限制。

Policy/Agent：在许可能力内选择行动，正确解释已读范围和未知；不能改 Actor、签发 Grant 或把模型总结写成权威事实。以上生产接入责任明确，但并非本包已实现这些基础设施。
